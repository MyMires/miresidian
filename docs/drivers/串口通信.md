# 串口通信

`miresidian_serial.dll` 是供测试平台加载的通用串口数据通信节点。它不包含任何特定仪器协议：调用方以数据格式参数指定平台文本如何转换为原始字节，节点负责发送、读取或执行原子查询。

数据格式转换由框架 `codec` 完成；串口租约代理仅传输原始字节及内部串口设置字段，两者职责独立。

本说明只描述发布 DLL 的功能与调用方法。所有字符串均须使用 UTF-8 编码。

## 发布包与加载条件

本说明在发布时固定复制到 `dist/串口通信/串口通信.md`，不在 x86 / x64 子目录中重复存放。可使用
`cargo dll 串口通信` 构建该节点的两个位数，或使用 `cargo dll32 串口通信`、`cargo dll64 串口通信`
分别构建一个位数。

| 平台进程位数 | 发布目录 | 应加载的文件 |
| --- | --- | --- |
| 64 位 | `dist/串口通信/windows-x64/` | `miresidian_serial.dll` 与 `miresidian.h` |
| 32 位 | `dist/串口通信/windows-x86/` | `miresidian_serial.dll` 与 `miresidian.h` |

DLL 的位数必须与测试平台进程一致。C/C++ 调用方以同目录的 `miresidian.h` 声明为准；它导出 `__cdecl` 调用约定的 C ABI。ABI 当前版本由 `miresidian_abi_version()` 返回，当前值为 `2`。

## 统一调用入口

所有节点操作均使用同一组 `function`、`config` 与 `input` 参数。DLL 提供三种结果输出入口：

```c
int32_t miresidian_invoke(
    const char *function,
    const char *const *config, size_t config_count,
    const char *const *input, size_t input_count,
    MiresidianTextArray *output);
```

`miresidian_invoke` 将结果合并为 `[错误码, 错误信息, ..业务输出]`。平台支持独立错误通道时应改用 `miresidian_invoke_with_error`：成功时 `output` 为业务输出、`error` 为空；失败时 `output` 为空、`error` 为 `[错误码, 错误信息]`。只需要业务输出时可使用 `miresidian_invoke_without_error`。三者的完整声明和所有权规则见 [C ABI](../c-abi.md)。

`function` 对应平台调用约定中的 `Function`，即操作名称；`config` 与 `input` 分别对应 `Config[]` 与 `Input[]`，是按顺序传入的字符串数组。没有配置或输入时，传入 `NULL, 0`。框架内部仍以 `operation` 组织 Rust 调度。所有返回数组均必须由调用方置零，并以 `miresidian_free_text_array` 释放。

```c
MiresidianTextArray output = {0};
int32_t status = miresidian_invoke(
    "GetFunctions", NULL, 0, NULL, 0, &output);

if (status == MIRESIDIAN_STATUS_OK) {
    // output.values[0] == "0"，output.values[1] 为空；业务输出从 values[2] 开始。
}
miresidian_free_text_array(&output);
```

三个 `miresidian_invoke*` 入口均在当前 DLL 实例内串行处理调用。因此同一 DLL 上的多线程调用会排队，调用方无需额外为同一实例加锁。

## 操作清单

先调用 `GetFunctions` 可从 DLL 取得当前版本实际支持的签名。当前发布版返回以下顺序和文本：

```text
GetFunctions()(函数列表)
GetInitConfig()(端口名称:COM1,波特率:9600,数据位:8,校验位:None,停止位:1,流控:None,超时毫秒:1000)
GetPortNO()(搜索结果,端口号)
InitDevice(端口名称:COM1,波特率:9600,数据位:8,校验位:None,停止位:1,流控:None,超时毫秒:1000)(状态)
CloseDevice()()
发送数据(发送数据,数据格式:UTF-8/Unicode/HEX/Base64)()
读取数据(数据格式:UTF-8/Unicode/HEX/Base64)(接收数据)
查询数据(发送数据,发送数据格式:UTF-8/Unicode/HEX/Base64,接收数据格式:UTF-8/Unicode/HEX/Base64)(接收数据)
```

| 操作 | Config | Input | Output | 用途 |
| --- | --- | --- | --- | --- |
| `GetFunctions` | 无 | 无 | `函数列表` | 返回上述格式的全部可调用操作签名。 |
| `GetInitConfig` | 无 | 无 | 7 个初始化配置定义 | 供平台生成初始化界面或默认值。 |
| `GetPortNO` | 无 | 无 | `搜索结果`、`端口号` | 枚举到至少一个串口时返回 `"1"` 和第一个端口名；未枚举到时返回 `"0"` 和空字符串。它不是设备识别，也不保证返回目标设备端口。 |
| `InitDevice` | 见下表 | 无 | `状态` | 建立串口租约并打开或接入已打开的物理串口。成功时输出例如 `已连接: COM1`。 |
| `CloseDevice` | 无 | 无 | 无 | 释放本调用方的串口租约；重复调用安全。 |
| `发送数据` | 无 | `发送数据`、`数据格式` | 无 | 将平台文本按指定格式转换为原始字节，完整写入并刷新到串口。 |
| `读取数据` | 无 | `数据格式` | `接收数据` | 读取原始字节直到本次读取超时，再按指定格式转换为平台文本。 |
| `查询数据` | 无 | `发送数据`、`发送数据格式`、`接收数据格式` | `接收数据` | 在一次独占事务中依次写入、刷新、读取；发送和接收可使用不同数据格式。 |

除 `InitDevice` 外，设备操作的 `config` 不参与处理，应传 `NULL, 0`。`CloseDevice` 后，必须再次执行 `InitDevice` 才能使用“发送数据”“读取数据”或“查询数据”。

## 初始化配置

`InitDevice` 的 `config` 必须按以下下标顺序传入。可省略末尾项目或传空字符串，驱动会采用默认值；也可传入 `名称:值` 形式，例如 `端口名称:COM3`。

| 下标 | 名称 | 默认值 | 允许值 |
| ---: | --- | --- | --- |
| 0 | 端口名称 | `COM1` | 操作系统可打开的串口名，例如 `COM3`。 |
| 1 | 波特率 | `9600` | 无符号整数，例如 `9600`、`115200`。 |
| 2 | 数据位 | `8` | `5`、`6`、`7`、`8`。 |
| 3 | 校验位 | `None-无校验/Odd-奇校验/Even-偶校验` | 平台查询描述时原样返回；实际调用时传入平台选择后的值，例如 `Odd`。 |
| 4 | 停止位 | `1` | `1` 或 `2`。 |
| 5 | 流控 | `None` | `None` / `Hardware` / `Software`；也接受“无流控”/“硬件流控”/“软件流控”。 |
| 6 | 超时毫秒 | `1000` | 无符号整数。用于本调用方后续读写操作的超时。 |

例如，以默认的 9600、8N1、无流控打开 `COM3`：

```c
const char *init_config[] = {
    "COM3", "9600", "8", "None", "1", "None", "1000"
};
MiresidianTextArray output = {0};
MiresidianTextArray error = {0};
int32_t status = miresidian_invoke_with_error(
    "InitDevice", init_config, 7, NULL, 0, &output, &error);
// 成功时 output.count == 1，output.values[0] 例如为“已连接: COM3”。
miresidian_free_text_array(&output);
miresidian_free_text_array(&error);
```

再次执行 `InitDevice` 会先关闭当前调用方已经持有的租约，再按新配置初始化。

## 数据收发示例

以下示例发送 `*IDN?\r\n`，并以 UTF-8 接收响应；接收在本次读取超时后结束：

```c
const char *query_input[] = { "*IDN?\r\n", "UTF-8", "UTF-8" };
MiresidianTextArray output = {0};
MiresidianTextArray error = {0};
int32_t status = miresidian_invoke_with_error(
    "查询数据", NULL, 0, query_input, 3, &output, &error);

if (status == MIRESIDIAN_STATUS_OK && output.count == 1) {
    const char *response = output.values[0];
    // 立即复制 response；随后释放 output。
}
miresidian_free_text_array(&output);
miresidian_free_text_array(&error);
```

数据格式由框架统一支持 UTF-8、Unicode、HEX、Base64 等表示。`发送数据` 成功时没有业务输出。对于读取和查询，返回字节将按接收数据格式转换；格式不匹配时调用失败，错误按所选入口规则写入合并数组或 `error` 数组。

## 多个 DLL 对同一串口的调用

即使 `串口通信1.dll` 与 `串口通信2.dll` 位于不同目录，只要运行在同一台主机，它们仍可经由各自的 `InitDevice`、读写操作和 `CloseDevice` 共享同一个串口。调用方不需要增加额外入口。

共享同一端口时，端口名称、波特率、数据位、校验位、停止位和流控必须完全一致；不同调用方可使用不同的“超时毫秒”。同一物理端口的读写事务会被驱动串行化，“查询数据”的写入和读取保持为一个不可交叉的事务。最后一个调用方执行 `CloseDevice`（或其 DLL 调用连接结束）后，物理串口才会关闭。

## 失败与诊断

| 返回码 | 含义 | 调用方处理 |
| ---: | --- | --- |
| `0` (`MIRESIDIAN_STATUS_OK`) | 调用成功。 | 读取输出，再调用 `miresidian_free_text_array`。 |
| `1` (`MIRESIDIAN_STATUS_INVALID_ARGUMENT`) | ABI 指针、字符串编码或输出参数不符合要求。 | 检查 `Function`、数组指针、数组数量和 UTF-8 编码。 |
| `2` (`MIRESIDIAN_STATUS_OPERATION_FAILED`) | 操作名、生命周期、配置、串口访问或通信失败。 | 从合并数组或 `error` 数组读取错误文本，修正后重试或重新初始化。 |
| `3` (`MIRESIDIAN_STATUS_INTERNAL_ERROR`) | 驱动捕获到未预期的内部错误。 | 记录错误文本，关闭并重新初始化；持续出现时保留日志供排查。 |

错误不再通过线程本地接口传递。失败调用返回的数组同样必须通过 `miresidian_free_text_array` 释放；将零初始化的数组传入该函数是安全的。

推荐的生命周期为：`GetFunctions` / `GetInitConfig`（可选）→ `InitDevice` → 任意次读写或查询 → `CloseDevice`。无论中途是否出错，调用方结束时都应调用 `CloseDevice`。
