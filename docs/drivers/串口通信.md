# 串口通信

`miresidian_serial.dll` 是通用串口通信节点。它不绑定特定仪器协议：平台以文本和数据格式
传入请求，节点负责原始字节的串口发送、读取与查询。

发布时，本文件复制为 `dist/串口通信/串口通信.md`。64 位 DLL 位于
`dist/串口通信/windows-x64/`，32 位 DLL 位于 `dist/串口通信/windows-x86/`；测试平台
进程位数必须与加载的 DLL 一致。

## DLL 调用方式

DLL 导出 `miresidian_abi_version` 与 `miresidian_invoke`。ABI 版本当前为 `5`，完整 C 声明见随发布包提供的
`miresidian.h` 与 [C ABI](../c-abi.md)。

唯一入口使用：

```text
result = miresidian_invoke(function, config_json, input_json)
```

### ABI 函数签名与参数

```c
uint32_t miresidian_abi_version(void);

const char *miresidian_invoke(
    const char *function,
    const char *config_json,
    const char *input_json);
```

| 项目 | C 类型 | 含义与传入规则 |
| --- | --- | --- |
| `function` | `const char *` | UTF-8 操作名称，例如 `GetFunctions`、`GetInitConfig`、`InitDevice` 或节点操作名称。 |
| `config_json` | `const char *` | UTF-8 JSON 字符串数组，对应 Config 通道。例如 `["COM3","115200"]`；无配置传 `[]`，也可传 `NULL`。 |
| `input_json` | `const char *` | UTF-8 JSON 字符串数组，对应 Input 通道。例如 `["01 03 00 00","HEX"]`；无输入传 `[]`，也可传 `NULL`。 |
| `result` | `const char *` | 函数返回的 UTF-8 JSON 文本。DLL 在当前线程持有其内存；调用方须立即复制文本，不得释放指针。 |

`result` 是 `miresidian_invoke` 的返回值名称，不是 JSON 字段名。其内容固定包含
`status`、`message`、`output`：

```json
{
  "status": 0,
  "message": "",
  "output": ["业务输出1", "业务输出2"]
}
```

| JSON 字段 | 类型 | 含义 |
| --- | --- | --- |
| `status` | 整数 | `0` 成功；`1` 参数无效；`2` 操作失败；`3` 内部错误。 |
| `message` | 字符串 | 成功时为空字符串；失败时为诊断信息。 |
| `output` | 字符串数组 | 节点方法的有序业务输出；失败时为空数组。 |

DLL 不接收输出缓冲区，也没有输出容量参数；平台不需要初始化输出数组或传入缓冲区大小。

### LabVIEW 2016 中文界面配置

在“调用库函数”节点中选择与 LabVIEW 进程位数一致的 DLL：32 位 LabVIEW 使用
`windows-x86/miresidian_serial.dll`，64 位 LabVIEW 使用 `windows-x64/miresidian_serial.dll`。

“函数”页：函数名填 `miresidian_invoke`，调用规范选择“C”，线程选择“在 UI 线程中运行”。

“参数”页按以下顺序配置：

| 名称 | 类型 | 数据类型 | 方向 |
| --- | --- | --- | --- |
| `result`（返回类型） | 字符串 | C 字符串指针 | 返回值 |
| `function` | 字符串 | C 字符串指针 | 输入 |
| `config_json` | 字符串 | C 字符串指针 | 输入 |
| `input_json` | 字符串 | C 字符串指针 | 输入 |

函数返回后立即将 `result` 保存为 LabVIEW 字符串，再解析其中的 `status`、`message`、
`output`。不要为此函数添加 `output_json`、`output_capacity` 或 U8 输出数组参数。

调用方应使用本节上方的 ABI 参数表传入三个 UTF-8 字符串，并在同一线程下一次调用前复制 `result`。

| 入口 | 成功结果 | 失败结果 |
| --- | --- | --- |
| `miresidian_invoke` | `result = {"status":0,"message":"","output":[..业务输出]}` | `result = {"status":错误码,"message":"错误信息","output":[]}` |

调用 `miresidian_invoke` 查询操作列表示例：

```c
const char *response = miresidian_invoke("GetFunctions", "[]", "[]");
/* response 是 DLL 持有的 JSON 文本；立即复制后再解析。 */
```

`GetFunctions`、`GetInitConfig` 与 `GetPortNO` 为常驻查询，不需要先调用 `InitDevice`；其余串口通信操作需要先初始化。

先调用 `GetFunctions` 获取当前 DLL 的完整签名。发布版包含：

| 操作 | Config | Input | Output | 说明 |
| --- | --- | --- | --- | --- |
| `GetFunctions` | 无 | 无 | 函数列表 | 返回可调用操作签名。 |
| `GetInitConfig` | 无 | 无 | 初始化配置 | 返回 `InitDevice` 所需配置描述。 |
| `GetPortNO` | 无 | 无 | 搜索结果、端口号 | 返回第一个可见串口；不是设备识别保证。 |
| `InitDevice` | 初始化配置 | 无 | 状态 | 建立串口租约并打开或接入物理端口。 |
| `CloseDevice` | 无 | 无 | 无 | 释放本调用方租约；重复调用安全。 |
| `发送数据` | 无 | 发送数据、数据格式 | 无 | 将文本编码为字节后完整写入串口。 |
| `读取数据` | 无 | 数据格式、接收方式等 | 接收数据 | 按接收策略读取字节，再编码为平台文本。 |
| `查询数据` | 无 | 发送数据、收发格式与接收方式等 | 接收数据 | 在独占事务中依次写入并读取。 |
| `获取串口状态` | 无 | 无 | 连接状态、待读字节数、待写字节数 | 查询当前连接状态。 |
| `清空缓冲区` | 无 | 缓冲区方向 | 无 | 清空输入、输出或两者缓冲区。 |
| `设置控制信号` | 无 | DTR 状态、RTS 状态、中断状态 | 无 | 修改或保持串口控制信号。 |

## 初始化配置

`InitDevice` 的 `Config[]` 按以下顺序传值。可省略尾部项目或传空字符串使用默认值；允许传入
裸值或 `名称:值`。

| 下标 | 参数描述 | 默认值 | 调用值示例 |
| ---: | --- | --- | --- |
| 0 | `端口名称:COM1` | `COM1` | `COM3` |
| 1 | `波特率:9600` | `9600` | `115200` |
| 2 | `数据位:8/7/6/5` | `8` | `7` |
| 3 | `校验位:None-无校验/Odd-奇校验/Even-偶校验` | `None` | `Odd` |
| 4 | `停止位:1-1位/2-2位` | `1` | `2` |
| 5 | `流控:None-无/Software-软件/Hardware-硬件` | `None` | `Hardware` |
| 6 | `读取超时/ms:1000` | `1000` | `500` |
| 7 | `写入超时/ms:1000` | `1000` | `500` |

参数描述在 `GetFunctions`、`GetInitConfig` 查询时原样返回。例如平台显示
`Odd-奇校验` 后，调用 `InitDevice` 时传入的实际文本是 `Odd`，不是完整描述。数据格式的
`ASCII/GBK/UTF-8/Unicode/HEX/Base64` 中实际值与显示值相同，因此只写一次。

## 使用顺序与共享租约

推荐调用顺序为：`GetFunctions` / `GetInitConfig`（可选）→ `InitDevice` → 任意次发送、读取或
查询 → `CloseDevice`。需要连接的操作在关闭后必须再次初始化。

不同目录中的多个串口 DLL 实例可通过租约代理共享同一物理串口。共享时端口名称、波特率、
数据位、校验位、停止位与流控必须一致；同一端口的读写事务会串行化，`查询数据` 的发送和读取
保持为不可交叉的事务。最后一个租约释放后物理串口关闭。
