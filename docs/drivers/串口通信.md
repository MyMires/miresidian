# 串口通信

执行项目根目录中的 `cargo dll` 或 `cargo dll32` 后，会自动生成可直接交付测试平台的发布包：

```text
dist/
└── 串口通信/                             # 名称来自 #[miresidian::node("串口通信")]
    ├── windows-x64/                      # cargo dll
    │   ├── miresidian_serial.dll
    │   ├── miresidian.h
    │   └── 串口通信.md
    └── windows-x86/                      # cargo dll32
        ├── miresidian_serial.dll
        ├── miresidian.h
        └── 串口通信.md
```

## 功能

此实例库提供“串口通信”设备节点。测试平台以 C ABI 加载 `miresidian_serial.dll`，通过统一入口 `miresidian_invoke_v1` 调用节点能力；接口协议、内存释放规则和状态码见同目录的 `miresidian.h`。

## 测试平台部署

1. 测试平台是 64 位时，复制 `dist/串口通信/windows-x64/` 的全部文件；32 位时复制 `dist/串口通信/windows-x86/` 的全部文件。
2. DLL 位数必须与加载它的测试平台进程一致；64 位进程不能加载 32 位 DLL，反之亦然。
3. 调用 `miresidian_invoke_v1` 后，使用 `miresidian_free_output_v1` 释放返回内容；失败时通过 `miresidian_last_error_v1` 读取 UTF-8 错误信息。
4. 调用约定和 Operation/Config/Input/Output 映射以 `miresidian.h` 为准。

## 重新生成

```bash
cargo dll    # Windows x64
cargo dll32  # Windows x86（32 位）
```

发布工具从 `#[miresidian::node("串口通信")]` 读取节点名称并自动决定目录及说明文件名；更换宏内的名称后，下一次打包会同步使用新名称。
