# 串口通信

`miresidian_serial.dll` 是供测试平台加载的串口文本通信驱动。它不包含任何特定仪器协议：调用方传入 UTF-8 文本，驱动将文本写入串口或读取串口返回的 UTF-8 文本。

本说明只描述发布 DLL 的功能与调用方法。所有字符串均须使用 UTF-8 编码。

## 发布包与加载条件

本说明在发布时固定复制到 `dist/串口通信/串口通信.md`，不在 x86 / x64 子目录中重复存放。可使用
`cargo dll 串口通信` 构建该节点的两个位数，或使用 `cargo dll32 串口通信`、`cargo dll64 串口通信`
分别构建一个位数。

| 平台进程位数 | 发布目录 | 应加载的文件 |
| --- | --- | --- |
| 64 位 | `dist/串口通信/windows-x64/` | `miresidian_serial.dll` 与 `miresidian.h` |
| 32 位 | `dist/串口通信/windows-x86/` | `miresidian_serial.dll` 与 `miresidian.h` |

DLL 的位数必须与测试平台进程一致。C/C++ 调用方以同目录的 `miresidian.h` 声明为准；它导出 `__cdecl` 调用约定的 C ABI。ABI 当前版本由 `miresidian_abi_version()` 返回，当前值为 `1`。

## 统一调用入口

所有功能均经由下列函数调用：

```c
int32_t miresidian_invoke_v1(
    const char *operation,
    const char *const *config, size_t config_count,
    const char *const *input, size_t input_count,
    MiresidianOutputV1 *output);
```

`operation` 为操作名称；`config` 和 `input` 分别是按顺序传入的字符串数组。没有配置或输入时，传入 `NULL, 0`。`output` 必须由调用方置零；成功后其中的 `values[0..count]` 是按操作定义顺序返回的 UTF-8 字符串。

成功调用完成后，必须执行一次 `miresidian_free_output_v1(&output)` 释放驱动分配的输出内存。不得使用平台自己的释放函数释放 `values` 或其中任何字符串。

```c
MiresidianOutputV1 output = {0};
int32_t status = miresidian_invoke_v1(
    "GetFunctions", NULL, 0, NULL, 0, &output);

if (status == MIRESIDIAN_STATUS_OK) {
    // output.values[0] 至 output.values[output.count - 1] 为 UTF-8 字符串。
}
miresidian_free_output_v1(&output);
```

`miresidian_invoke_v1` 在当前 DLL 实例内串行处理调用。因此同一 DLL 上的多线程调用会排队，调用方无需额外为同一实例加锁。

## 操作清单

先调用 `GetFunctions` 可从 DLL 取得当前版本实际支持的签名。当前发布版返回以下顺序和文本：

```text
GetFunctions()(函数列表)
GetInitConfig()(端口名称:COM1,波特率:9600,数据位:8,校验位:None,停止位:1,流控:None,超时毫秒:1000)
GetPortNO()(搜索结果,端口号)
InitDevice(端口名称:COM1,波特率:9600,数据位:8,校验位:None,停止位:1,流控:None,超时毫秒:1000)(状态)
CloseDevice()()
写入文本(发送文本)(写入字节数)
读取文本(最大接收字节数:1024)(接收文本)
查询文本(发送文本,最大接收字节数:1024)(接收文本)
```

| 操作 | Config | Input | Output | 用途 |
| --- | --- | --- | --- | --- |
| `GetFunctions` | 无 | 无 | `函数列表` | 返回上述格式的全部可调用操作签名。 |
| `GetInitConfig` | 无 | 无 | 7 个初始化配置定义 | 供平台生成初始化界面或默认值。 |
| `GetPortNO` | 无 | 无 | `搜索结果`、`端口号` | 枚举到至少一个串口时返回 `"1"` 和第一个端口名；未枚举到时返回 `"0"` 和空字符串。它不是设备识别，也不保证返回目标设备端口。 |
| `InitDevice` | 见下表 | 无 | `状态` | 建立串口租约并打开或接入已打开的物理串口。成功时输出例如 `已连接: COM1`。 |
| `CloseDevice` | 无 | 无 | 无 | 释放本调用方的串口租约；重复调用安全。 |
| `写入文本` | 无 | `发送文本` | `写入字节数` | 将 UTF-8 文本完整写入并刷新到串口。 |
| `读取文本` | 无 | `最大接收字节数` | `接收文本` | 从串口读取至多指定字节，再按 UTF-8 解码。 |
| `查询文本` | 无 | `发送文本`、`最大接收字节数` | `接收文本` | 在一次独占事务中依次写入、刷新和读取，适合请求—应答式设备。 |

除 `InitDevice` 外，设备操作的 `config` 不参与处理，应传 `NULL, 0`。`CloseDevice` 后，必须再次执行 `InitDevice` 才能使用“写入文本”“读取文本”或“查询文本”。

## 初始化配置

`InitDevice` 的 `config` 必须按以下下标顺序传入。可省略末尾项目或传空字符串，驱动会采用默认值；也可传入 `名称:值` 形式，例如 `端口名称:COM3`。

| 下标 | 名称 | 默认值 | 允许值 |
| ---: | --- | --- | --- |
| 0 | 端口名称 | `COM1` | 操作系统可打开的串口名，例如 `COM3`。 |
| 1 | 波特率 | `9600` | 无符号整数，例如 `9600`、`115200`。 |
| 2 | 数据位 | `8` | `5`、`6`、`7`、`8`。 |
| 3 | 校验位 | `None` | `None` / `Odd` / `Even`；也接受“无校验”/“奇校验”/“偶校验”。 |
| 4 | 停止位 | `1` | `1` 或 `2`。 |
| 5 | 流控 | `None` | `None` / `Hardware` / `Software`；也接受“无流控”/“硬件流控”/“软件流控”。 |
| 6 | 超时毫秒 | `1000` | 无符号整数。用于本调用方后续读写操作的超时。 |

例如，以默认的 9600、8N1、无流控打开 `COM3`：

```c
const char *init_config[] = {
    "COM3", "9600", "8", "None", "1", "None", "1000"
};
MiresidianOutputV1 output = {0};
int32_t status = miresidian_invoke_v1(
    "InitDevice", init_config, 7, NULL, 0, &output);
// 成功时 output.count == 1，output.values[0] 例如为“已连接: COM3”。
miresidian_free_output_v1(&output);
```

再次执行 `InitDevice` 会先关闭当前调用方已经持有的租约，再按新配置初始化。

## 文本收发示例

以下示例发送 `*IDN?\r\n`，并接收最多 1024 字节的文本响应：

```c
const char *query_input[] = { "*IDN?\r\n", "1024" };
MiresidianOutputV1 output = {0};
int32_t status = miresidian_invoke_v1(
    "查询文本", NULL, 0, query_input, 2, &output);

if (status == MIRESIDIAN_STATUS_OK && output.count == 1) {
    const char *response = output.values[0];
    // 立即复制 response；随后释放 output。
}
miresidian_free_output_v1(&output);
```

`发送文本` 不能为空。`最大接收字节数` 缺失或为空时为 `1024`，且必须大于 0。返回字节若不是有效 UTF-8 文本，调用失败；二进制协议目前不应使用此 DLL 的文本操作。

## 多个 DLL 对同一串口的调用

即使 `串口通信1.dll` 与 `串口通信2.dll` 位于不同目录，只要运行在同一台主机，它们仍可经由各自的 `InitDevice`、读写操作和 `CloseDevice` 共享同一个串口。调用方不需要增加额外入口。

共享同一端口时，端口名称、波特率、数据位、校验位、停止位和流控必须完全一致；不同调用方可使用不同的“超时毫秒”。同一物理端口的读写事务会被驱动串行化，“查询文本”的写入和读取保持为一个不可交叉的事务。最后一个调用方执行 `CloseDevice`（或其 DLL 调用连接结束）后，物理串口才会关闭。

## 失败与诊断

| 返回码 | 含义 | 调用方处理 |
| ---: | --- | --- |
| `0` (`MIRESIDIAN_STATUS_OK`) | 调用成功。 | 读取输出，再调用 `miresidian_free_output_v1`。 |
| `1` (`MIRESIDIAN_STATUS_INVALID_ARGUMENT`) | ABI 指针、字符串编码或输出参数不符合要求。 | 检查 `operation`、数组指针、数组数量和 UTF-8 编码。 |
| `2` (`MIRESIDIAN_STATUS_OPERATION_FAILED`) | 操作名、生命周期、配置、串口访问或通信失败。 | 立刻读取 `miresidian_last_error_v1()`，修正后重试或重新初始化。 |
| `3` (`MIRESIDIAN_STATUS_INTERNAL_ERROR`) | 驱动捕获到未预期的内部错误。 | 记录错误文本，关闭并重新初始化；持续出现时保留日志供排查。 |

失败时通过 `miresidian_last_error_v1()` 获取当前调用线程的错误文本。该指针由 DLL 管理，下一次同线程 ABI 调用后可能失效；如需保存，调用方必须立即复制。失败调用也不应调用 `miresidian_free_output_v1` 以外的释放函数；将零初始化的 `output` 传入该释放函数是安全的。

推荐的生命周期为：`GetFunctions` / `GetInitConfig`（可选）→ `InitDevice` → 任意次读写或查询 → `CloseDevice`。无论中途是否出错，调用方结束时都应调用 `CloseDevice`。
