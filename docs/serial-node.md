# 串口通信节点

串口通信的公开方法契约不在本文件或传输层手写；见[宏驱动开发](宏驱动开发.md)。实际声明位于 `constellation/serial/src/lib.rs` 的方法标注中，由 `node_impl` 编译期生成。

`SerialNode` 是不绑定具体仪器协议的串口通信节点，底层采用成熟的跨平台 `serialport` crate。它负责打开串口、设置通信参数、枚举端口以及 UTF-8 文本收发；设备命令、帧边界、校验和和二进制协议由上层具体节点实现。

## 初始化配置

`InitDevice` 按以下顺序接收配置；缺省或空值会使用默认值。平台也可传入 `标签:值` 形式，例如 `波特率:57600`。

| 顺序 | 标签 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 1 | 端口名称 | `COM1` | Windows 示例为 `COM3`；Linux 使用设备路径，例如 `/dev/ttyUSB0`。 |
| 2 | 波特率 | `9600` | 无符号整数。 |
| 3 | 数据位 | `8` | 支持 `5`、`6`、`7`、`8`。 |
| 4 | 校验位 | `None` | 支持 `None`、`Odd`、`Even`，以及中文的无/奇/偶校验写法。 |
| 5 | 停止位 | `1` | 支持 `1` 或 `2`。 |
| 6 | 流控 | `None` | 支持 `None`、`Hardware`、`Software`，以及中文写法。 |
| 7 | 超时毫秒 | `1000` | 读写超时，单位为毫秒。 |

## 操作

| Operation | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `写入文本` | 发送文本 | 写入字节数 | 写入并刷新 UTF-8 文本。 |
| `读取文本` | 最大接收字节数，默认 `1024` | 接收文本 | 读取一次串口缓冲区，返回严格有效的 UTF-8 文本。 |
| `查询文本` | 发送文本、最大接收字节数 | 接收文本 | 在同一节点实例中按“写入后读取”执行。 |

`GetPortNO` 使用临时节点列举系统串口，并返回第一个可见端口；调用不会保留打开的串口。

## 跨 DLL 共享租约

测试平台仍只通过统一入口调用 `InitDevice`、普通 Operation 与 `CloseDevice`，不需要调用额外的租约 API。

- 第一个成功初始化的 Miresidian 串口 DLL 会在本机回环端点启动串口代理，并由代理唯一打开物理串口。
- 其他目录中的同类 DLL 在其 `InitDevice` 中连接同一代理；同一端口仅当波特率、数据位、校验位、停止位与流控完全一致时允许共享。
- 每个租约保留自己的超时设置。“写入文本”“读取文本”与完整的“查询文本”均由代理在端口级锁内执行，因此不同 DLL 的收发不会交叉。
- `CloseDevice` 或 DLL 客户端连接断开会释放对应租约；最后一个租约释放后，代理关闭物理串口。

该机制用于同一台主机上的 Miresidian DLL。不同测试平台进程也可通过本机回环端点连接同一代理，但端点协议只面向本地调用，不是网络服务。

## 限制

当前版本刻意不把原始二进制数据伪装为文本。设备返回非 UTF-8 内容时，“读取文本”与“查询文本”会返回明确错误，避免静默损坏数据。字节数组的 C ABI 编解码确定后，将补充二进制读写操作。
