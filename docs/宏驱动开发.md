# 宏驱动开发

Miresidian 的驱动公开契约由方法签名和可选标注声明，驱动作者不得手写 `GetFunctions`、`GetInitConfig`、操作字符串分发或 C ABI 入口。`#[miresidian::node_impl]` 在编译期读取这些信息并生成对应内容。

参数标注中的平台描述文本必须原样透传；实际值与显示值的顺序等固定规则见[平台调用契约](platform-contract.md)。

描述中实际值与显示值相同时只写一次，如 `数据格式:ASCII/GBK/UTF-8`；只有二者不同才写为
`实际值-显示值`。物理量单位写为 `名称/单位:默认值`，如 `读取超时/ms:1000`；“字节数”等
计数保持普通 `名称:默认值` 形式。

## 职责边界

一个可发布节点由三个层次协作完成：

| 层次 | 责任 | 不应承担的责任 |
| --- | --- | --- |
| `miresidian` 运行时 | 生命周期、文本类型转换、调用契约、C ABI 支撑 | 任何特定通信库或设备协议 |
| `miresidian_macro` | 读取标注，生成描述信息、`DeviceNode` 调度和 DLL 导出 | 具体设备通信、端口或协议状态 |
| `constellation/<节点>` | 节点状态、通信实现、方法标注和该节点测试 | 手写平台函数列表、字符串分发或 ABI 导出 |

宏实现位于 `macro/src/`。`node_impl.rs` 只编排生成步骤；属性解析在
`node_impl/definition.rs`，自动命名在 `naming.rs`，平台描述在 `descriptor.rs`，调用调度在
`dispatch.rs`，C ABI 导出在 `ffi.rs`。新增标注行为或平台规则时，必须修改其所属模块，不得重新
将逻辑堆回编排入口。

宏只负责编译期语法检查与代码生成，不实现运行时数据转换。生成的参数调度统一调用
`miresidian::codec::decode_value_with_definition`，返回值统一调用
`miresidian::codec::encode_value`。`decode_value` 对 Config 与 Input 使用同一套规则，因此数值进制、数组转义、Base64 和文本编码规则只
维护在根框架的 `codec` 中，节点与宏项目均不得复制实现。

## 声明方式

```rust
#[miresidian::node("示例设备")]
#[derive(Default)]
pub struct ExampleNode {
    // 驱动状态与通信对象。
}

#[miresidian::node_impl]
impl ExampleNode {
    fn init_device(
        &mut self, address: String, port: u16,
    ) -> MiresidianResult<String> {
        # let _ = (address, port);
        # Ok("已连接".to_owned())
    }

    fn close_device(&mut self) -> MiresidianResult<()> {
        Ok(())
    }

    #[miresidian::operation]
    fn query(
        &mut self,
        request: String,
        maximum_bytes: usize,
    ) -> MiresidianResult<String> {
        # let _ = (request, maximum_bytes);
        # Ok(String::new())
    }
}
```

`node` 的参数为 DLL 的平台展示名称。`node_impl` 识别以下约定方法：

| Rust 方法 | 平台操作 | 标注规则 |
| --- | --- | --- |
| `init_device` | `InitDevice` | 未标注参数自动从 Config 读取；可用 `input` 将单个参数改为从 Input 读取。 |
| `close_device` | `CloseDevice` | 未标注参数自动从 Input 读取；通常没有参数。 |
| （框架提供） | `CloseAllDevices` | 不需要节点方法；无参数，关闭并释放当前运行时的全部通道。 |
| `get_port_no` | `GetPortNO` | 可选；未标注参数自动从 Input 读取，且无需先初始化。 |
| 任意方法 | 自动 PascalCase 或标注名称 | 使用 `operation` 标记；未标注参数自动从 Input 读取。`config`、`input` 与 `output` 可分别指定参数通道、平台名称及默认值、输出名称。 |

宏自动生成固定的 `GetFunctions` 与 `GetInitConfig`，以及每个节点 DLL 的调用入口 `miresidian_invoke`、`miresidian_invoke_with` 和 `miresidian_abi_version`。入口使用 JSON 字符串数组与固定 JSON 响应对象，见 [C ABI](c-abi.md)。稳定 Rust 不允许把属性直接写在 `->` 后的返回类型上，因此 `output` 放在方法上、紧邻 `operation`。

### 标注规则

- `#[miresidian::node("名称")]` 必须标注在节点结构体上，名称用于平台显示和发布目录。可选 `platforms(AdapterType, ...)` 会把一个或多个实现 `PlatformAdapter + Default` 的适配器编译进 DLL，例如 `#[miresidian::node("名称", platforms(MyPlatformAdapter))]`。框架始终保留 TB 兼容适配器。
- C ABI 首次调用时按节点声明的适配器注册表创建运行时；外部方可通过 `miresidian_invoke` 的 `InitDevice` 保留 `平台适配` Config 选择 id，也可通过 `miresidian_invoke_with` 显式传入平台枚举值；后者不发布也不接受该 Config。
- `#[miresidian::node_impl]` 必须标注在该节点唯一的固有 `impl` 块上；其中必须声明
  `init_device` 与 `close_device`，两者的接收者均为 `&mut self`。
- `node_impl` 不能用于 trait `impl`，也暂不支持带泛型参数的 `impl`。节点 DLL 需要一个可在
  编译期确定的具体节点类型，以便生成唯一的静态运行时和 C ABI 入口。
- `#[miresidian::operation]` 不带参数时使用方法名自动转换后的平台名称；
  `#[miresidian::operation("名称")]` 使用显式名称。共享执行方式由框架自动追加到 `InitDevice` 的 `共享执行方式` 配置决定；驱动方法无需通过 `operation` 标注选择顺序、并行或广播。
- 未标注参数使用自动来源：`init_device` 默认从 Config 读取，其他固定入口与 `operation`
  默认从 Input 读取。`#[miresidian::config]` 与 `#[miresidian::input]` 可标注在任意平台方法的
  非 `self` 参数上，并逐参数覆盖该默认来源；两者都可写为 `("名称")` 或
  `("名称:默认值")`。同一参数不能同时标注两者。
- `#[miresidian::output("名称")]` 标注在方法上。一个标注可给出多个逗号分隔的输出名，
  数量应与返回值可展开的输出数量一致。

未带字符串的 `operation` 会把 Rust 方法名转换为测试平台的 PascalCase：`read_text` 变为 `ReadText`，`read_tcp_ip` 变为 `ReadTcpIp`。`init_device`、`close_device` 与 `get_port_no` 是固定平台入口，分别固定映射为 `InitDevice`、`CloseDevice`、`GetPortNO`；`CloseAllDevices` 由运行时固定提供，不对应节点方法；其中 `GetPortNO` 是唯一的缩写特例。

未使用 `config` 或 `input` 标注时，平台参数名同样自动转为 PascalCase，例如 `port_name` 为 `PortName`、`port_no` 为 `PortNo`。缺少 `output` 标注时，标量、字符串与数组返回值使用“返回值”；二元或三元元组按顺序自动生成“返回值1”“返回值2”“返回值3”；`MiresidianResult<()>` 自动生成空输出。显式 `output` 的名称数量必须与返回值输出数量完全一致，否则编译失败。

### 多通道与共享调用

`InitDevice` 的业务 Config 是运行时通道键；运行时会补齐默认值、移除 `名称:` 前缀并将选项显示值规范化为实际值，因而语义相同的配置会定位到同一通道。框架自动追加的共享执行方式不参与该键，也不传入节点初始化方法。普通自定义操作与 `CloseDevice` 可携带该保留末项，运行时会自动剥离后定位通道；操作上的 `#[miresidian::config]` 参数读取的是已连接通道的规范化 Config 值，声明顺序应与初始化配置保持一致。

需要一条步骤驱动多个已创建通道时，平台将 Input 组织为 `['共享', '通道 1 参数 1,通道 1 参数 2', '通道 2 参数 1,通道 2 参数 2']`。每个通道字符串按英文逗号分隔 Input 参数；参数内部的数组仍用 `|` 表示。空白、空参数、参数过多或缺少无默认值参数的通道不会执行，并在相应 Output 槽位返回空字符串。共享调用仅适用于 `operation`，不改变固定操作含义。广播方式要求全部有效通道参数串一致，仍按通道逐项返回输出。

例如，外部调用 `config = ["COM3", "2500"]`、`input = ["令牌", "*IDN?"]` 时，以下两个方法按各自参数标注取值，而不是按方法名称限制通道。`address` 与 `timeout_ms` 分别取 `config[0]`；`token` 与 `command` 分别取 `input[0]`：

```rust
fn init_device(
    &mut self,
    #[miresidian::config("设备地址")] address: String,
    #[miresidian::input("初始化令牌")] token: String,
) -> MiresidianResult<String> { # Ok(format!("{address}:{token}")) }

#[miresidian::operation("查询")]
fn query(
    &mut self,
    #[miresidian::input("命令")] command: String,
    #[miresidian::config("超时毫秒")] timeout_ms: u64,
) -> MiresidianResult<String> { # Ok(format!("{command}:{timeout_ms}")) }
```

## 可跨语言使用的类型

输入和输出 ABI 都是 UTF-8 文本。宏目前支持 `String`、`bool`、常用有符号/无符号整数、浮点数、`Option<T>` 和 `Vec<T>`。数组在平台侧使用 `|` 分隔，例如 `1|2|3`。`Vec<T>` 输出为一个 `|` 分隔的输出值；二元和三元元组可映射为多个输出值。

配置或输入标注中的 `名称:默认值` 会同时生成平台元数据，并用于缺失或空白参数的默认值解析。调用方仍可传裸值或 `名称:值`。
