Miresidian 的驱动公开契约由方法签名和可选标注声明，驱动作者不得手写 `GetFunctions`、`GetInitConfig`、操作字符串分发或 C ABI 入口。结构体上的 `#[miresidian::node]` 声明节点，方法上的 `#[miresidian::operation]` 独立读取签名并生成平台契约；框架汇总注册项并生成统一入口。

## 参数声明规范

参数标注中的平台描述文本必须原样透传；实际值与显示值的顺序等固定规则见[平台调用契约](c-abi.md#平台调用契约)。

描述中实际值与显示值相同时只写一次，如 `数据格式:ASCII/GBK/UTF_8`；只有二者不同才写为
`实际值-显示值`。同一参数的全部候选项，实际值的表达形式须统一，显示值的表达形式也须统一。物理量单位写为 `名称/单位:`，如 `读取超时/ms:`；计数可写为 `接收字节数:`。除下述首个业务 Config 要求外，路径、开放文本和连续数值的默认/预填位留空，由用户输入；真实有限离散选项才列出候选项。

非初始化首个业务 Config 的路径例如 `#[miresidian::config("文件路径:")] path: String`，不写默认路径、不列候选项，也不生成路径选择下拉框。生成的路径与调用示例优先使用 `/`，用户传入的路径按原文处理，框架不自动转换分隔符。倍率例如 `#[miresidian::input("倍率:")] value: f64`；科学计数法可作为实际输入，不能放在默认/候选描述中，避免连字符被选项映射语法误读。范围、业务约束和输入样例放在节点调用说明。

### 首个业务 Config 的默认值

初始化存在业务 Config 时，第一个业务 Config **必须在描述中声明非空、符合参数类型及业务约束的默认值**，供宿主预填，例如业务约定默认端口为 COM1 时写 `#[miresidian::config("端口名称:COM1")] port_name: String`。按参数实际来源和声明顺序确定首项，包含默认来自 Config 的未标注参数；Input、Handle 等框架追加字段不计入，无业务 Config 时不适用。

首项要求优先于路径、开放文本和连续数值预填留空的通用规范，其余参数沿用原规则。默认值须有业务依据，不用空白、占位文本或任意设备地址凑格式；有限选项明确宿主默认选择的具体项。声明、GetInitConfig 元数据和调用说明保持一致。该要求不指定实例键、不新增宏编译检查，也不使框架自动补值；宿主仍须传入实际参数，解析规则见[强类型参数](#强类型参数)。

## 职责边界

一个可发布节点由三个层次协作完成：

| 层次 | 责任 | 不应承担的责任 |
| --- | --- | --- |
| `miresidian` 运行时 | 生命周期、文本类型转换、调用契约、C ABI 支撑 | 任何特定通信库或资源协议 |
| `miresidian_macro` | 读取标注，生成描述信息、`Node` 调度和 DLL 导出 | 具体资源通信、端口或协议状态 |
| 独立 Node 项目 | 节点状态、通信实现、方法标注和该节点测试 | 手写平台函数列表、字符串分发或 ABI 导出 |

宏实现位于 `macro/src/`。`node.rs + node/` 负责结构体声明、节点绑定及 C ABI；
`operation.rs + operation/` 负责方法解析、自动命名、参数描述和调用包装。方法通过内部
inventory 注册表汇总，不扫描源码、不依赖宏展开顺序，也不要求额外的 impl 标记。

宏只负责编译期语法检查与代码生成，不实现运行时数据转换。生成的参数调度统一调用
`miresidian::codec::decode_value_with_definition`，返回值统一调用
`miresidian::codec::encode_value`。`decode_value` 对 Config 与 Input 使用同一套规则，因此数值进制、数组转义、Base64 和文本编码规则只
维护在根框架的 `codec` 中，节点与宏项目均不得复制实现。

## 声明方式

```rust
#[miresidian::node("示例节点")]
pub struct ExampleNode {
    // 驱动状态与通信对象。
}

impl ExampleNode {
    #[miresidian::operation]
    fn init_device(
        #[miresidian::config("地址:127.0.0.1")] address: String, port: u16,
    ) -> MiresidianResult<(Self, String)> {
        # let _ = (address, port);
        # Ok((Self {}, "已连接".to_owned()))
    }

    #[miresidian::operation]
    fn close_device(&mut self) -> MiresidianResult<()> {
        Ok(())
    }

    #[miresidian::operation]
    fn query(
        &mut self,
        request: String,
        maximum_bytes: usize,
    ) -> MiresidianResult<String> {
        # let _ = (request, maximum_bytes);
        # Ok(String::new())
    }
}
```

`node` 的参数为 DLL 的平台展示名称。方法级 `operation` 识别以下约定方法：

| Rust 方法 | 平台操作 | 标注规则 |
| --- | --- | --- |
| `init_device` | `InitDevice` | 未标注参数自动从 Config 读取；可用 `input` 将单个参数改为从 Input 读取。 |
| `close_device` | `CloseDevice` | 未标注参数自动从 Input 读取；通常没有参数。 |
| （框架提供） | `CloseAllDevices` | 不需要节点方法；无参数，关闭并释放当前运行时的全部通道。 |
| `get_port_no` | `GetPortNO` | 可选；未标注参数自动从 Input 读取，且无需先初始化。 |
| 任意方法 | 自动 PascalCase 或标注名称 | 使用 `operation` 标记；未标注参数自动从 Input 读取。`config`、`input` 与 `output` 可分别指定参数通道、平台名称及描述、输出名称。 |

宏自动生成固定的 `GetFunctions` 与 `GetInitConfig`，以及每个节点 DLL 的调用入口 `miresidian_invoke_request`、`miresidian_invoke`、`miresidian_invoke_with` 和 `miresidian_abi_version`。0.26.0 / macro 0.23.0 起提供完整请求 JSON 对象入口（C ABI v8），两个既有入口继续接收分开的操作名和 JSON 字符串数组，全部返回固定 JSON 响应对象，见 [C ABI](c-abi.md)。稳定 Rust 不允许把属性直接写在 `->` 后的返回类型上，因此 `output` 放在方法上、紧邻 `operation`。

### feature 宏简写（0.28.0 起）

本节对应根框架 0.28.0 / macro 0.24.0 源码，尚未发布；旧节点继续按依赖版本使用旧长写。Cargo features 不因标注自动启用。

```rust,ignore
#[miresidian::node("设备", instances(multiple, config), lease)]
#[miresidian::input("数据", batch, format(hex))]
#[miresidian::output("结果", format(utf8, hex, base64, selector = "结果格式"))]
```

| 声明 | 归一后的含义 |
| --- | --- |
| 不写 instances | 默认单对象，不接受多通道 |
| instances 或 instances() | 单对象，固定顺序多通道 |
| instances(parallel) | 单对象，固定并行调度；同对象业务仍互斥 |
| instances(selectable(sequential)) | 单对象，执行方式可选且默认顺序 |
| instances(multiple, config) | Config 组合键多对象，固定顺序 |
| instances(multiple, handle, selectable(broadcast)) | Handle 多对象，可选执行且默认广播 |
| lease 或 lease(required) | 固定租约，不发布访问方式选择器 |
| lease(disabled) | 固定直连 |
| lease(selectable(required)) | 可选 Lease/Direct，默认 Lease |
| format(hex) | 固定格式，不增加格式选择 Input |
| format(utf8, hex, base64, selector = "数据格式") | 多格式，首项默认，显式命名选择 Input |

instances 的模式、关联和执行策略按不同取值域解析；省略模式为 single、省略策略为固定 sequential，multiple 必须明确 config/handle，single 禁止关联项。selectable 必须提供一个合法默认策略。旧长写 `mode/binding/execution/default_execution` 的必填项保持原规则，不套用短写默认值。实例与通道的区别见[实例管理](instances.md)。

lease 只增加已存在策略的等价短写：不声明时保持 Direct，裸标记要求 feature 与资源键；旧 resource/configuration 配对列表仍兼容，禁止和参数角色混用。`lease(selectable(disabled))` 未提供；类型级租约和参数级 lease(key/ignore) 的职责仍分别处理，详见[Config 身份](config-identity.md)。

format 支持 ascii、gbk、utf8、utf16le、hex、base64，旧 `format(formats = [...], selector = "...")` 完整兼容。新写法先列格式再写 selector，多格式必须 selector、单格式禁止 selector。输入选择器跟随数据，输出选择器追加到方法 Input 末尾；新旧槽位、选项顺序及默认项一致。输入可与 batch 组合，名称之后 batch 与 format 的先后不影响布局。

重复 feature、策略、格式及混用同组长短语法均编译报错；参数说明继续直接附着对应 config/input，不集中到方法上。方法仍须逐个标记 operation，output 标签保持现状。

### 标注规则

- `#[miresidian::node("名称")]` 必须标注在节点结构体上，名称用于平台显示和发布目录。可选 `platforms(AdapterType, ...)` 会把一个或多个实现 `PlatformAdapter + Default` 的适配器编译进 DLL，例如 `#[miresidian::node("名称", platforms(MyPlatformAdapter))]`。框架始终保留 TB 兼容适配器。
- C ABI 首次调用时按节点声明的适配器注册表创建运行时；外部方可通过 `miresidian_invoke` 的 `InitDevice` 保留 `平台适配` Config 选择 id，也可通过 `miresidian_invoke_with` 显式传入非零平台枚举值，此时不发布也不接受该 Config。框架 0.27.0 / C ABI v9 起，`miresidian_invoke_with` 传 0 或 `miresidian_invoke_request` 省略/传零值 platform 均沿用前者流程：宿主查询并展示可选平台，InitDevice 传入所选文本，后续使用已选适配器。非零数值字段沿用后者；不接受 null 或平台名称字符串。节点不增加新标注，共用同一个运行时。发行状态按[版本查阅入口](README.md#按实际版本查阅)核对。
- 移除 `node_impl`。节点及其平台方法保留在同一模块，一个模块声明一个具体节点，允许拆为多个固有 `impl`；其他模块的普通辅助类型不受影响。节点结构体与平台方法不能带泛型参数，也不能把 operation 用于 trait impl。
- `init_device` 与 `close_device` 必须标注 `#[miresidian::operation]`；缺失对应桥接会在编译期报错。初始化是无 self 的关联函数，返回 `MiresidianResult<Self>` 或 `MiresidianResult<(Self, T)>`；关闭及普通业务方法仍以 `&mut self` 为接收者。节点无需实现 `Default`，框架也不自动生成它。
- 可选的 `get_port_no` 同样标注 operation，使用无 self 的关联函数；探测过程中取得的临时资源由函数自行回收，不创建或关闭节点实例。
- `#[miresidian::operation]` 不带参数时使用方法名自动转换后的平台名称；
  `#[miresidian::operation("名称")]` 使用显式名称。多通道执行由节点级 `instances(...)` 声明；只有 selectable 才在 `InitDevice` 发布执行方式配置；驱动方法无需通过 `operation` 标注选择顺序、并行或广播。
- 未标注参数使用自动来源：`init_device` 默认从 Config 读取，其他固定入口与 `operation`
  默认从 Input 读取。`#[miresidian::config]` 与 `#[miresidian::input]` 可标注在任意平台方法的
  非 `self` 参数上，并逐参数覆盖该默认来源；两者都可写为 `("名称")` 或
  `("名称:平台描述")`。冒号后的内容原样发布，不生成运行时默认值。同一参数不能同时标注两者。
- `#[miresidian::output("名称")]` 标注在方法上。一个标注可给出多个逗号分隔的输出名，
  数量应与返回值可展开的输出数量一致。

未带字符串的 `operation` 会把 Rust 方法名转换为测试平台的 PascalCase：`read_text` 变为 `ReadText`，`read_tcp_ip` 变为 `ReadTcpIp`。`init_device`、`close_device` 与 `get_port_no` 是固定平台入口，分别固定映射为 `InitDevice`、`CloseDevice`、`GetPortNO`；`CloseAllDevices` 由运行时固定提供，不对应节点方法；其中 `GetPortNO` 是唯一的缩写特例。

未使用 `config` 或 `input` 标注时，平台参数名同样自动转为 PascalCase，例如 `port_name` 为 `PortName`、`port_no` 为 `PortNo`。缺少 `output` 标注时，标量、字符串与数组返回值使用“返回值”；二元或三元元组按顺序自动生成“返回值1”“返回值2”“返回值3”；`MiresidianResult<()>` 自动生成空输出。显式 `output` 的名称数量必须与返回值输出数量完全一致，否则编译失败。

### 初始化输出与方法注册

初始化返回的 `Self` 只由运行时保存，不是平台输出。返回 `MiresidianResult<Self>` 时无业务输出；返回 `MiresidianResult<(Self, T)>` 时，仅 T 按原有规则编码和发布 output 名称。多个业务输出使用 `T = (A, B, ...)`，例如返回 `(Self, (String, u32))` 时 output 仍声明两个名称。

config、input、output 的写法、参数来源、名称、输出数量和编解码规则沿用统一契约；业务默认值不从描述推导；output 位于 operation 前后均可。初始化函数因取消 self，不会跳过第一个业务参数。初始化 Input 不参与对象身份：相同规范化业务 Config 命中已有对象时直接复用，不再执行初始化方法，也不重新应用 Input；默认单实例的替换与失败边界见[默认单实例](instances.md#默认单实例)。

业务方法通过内部 inventory 注册项汇总，按照 `(源码文件、行、列)` 排序，同一文件保持声明顺序；cfg 或 cfg_attr 禁用的方法不会遗留注册。运行时在查询或执行前拒绝重复的平台名称和框架保留名称，不任意选取一个处理器。

[inventory 0.3.24](https://github.com/dtolnay/inventory) 使用 MIT OR Apache-2.0，兼容 MSRV 1.89，注册后端支持项目所需的 Linux/Windows；采用成熟库封装链接保留和元数据注册，避免手写平台段布局。加载时只注册元数据与函数指针，不建立资源连接、获取租约或调用业务。第三方接口仅通过隐藏宏支持项使用，不是节点的稳定公共 API。发布时须验证 x64/x86 DLL 的实际链接、加载与注册保留，交叉检查不能代替加载验证。

### 固定入口的实现与失败边界

下表描述节点作者需要实现的方法；所有方法均使用 operation 标注。具体设备发现和连接协议由业务模块实现，契约方法只委托业务对象。

| 方法 | 必需性、签名与职责 |
| --- | --- |
| `init_device` | 必需；无 self 的关联函数，返回 `MiresidianResult<Self>` 或 `MiresidianResult<(Self, T)>`。参数默认来自 Config，可逐项改为 Input。验证配置并取得业务所需资源；返回的 Self 归运行时持有，仅 T 成为业务输出。返回实例前失败由构造函数回滚，返回后失败的清理见下文异常边界。 |
| `close_device` | 必需；使用 `&mut self`，返回 `MiresidianResult<()>`，无业务输出。通常不接收参数；框架内部清理传空 Input，不能依赖额外必填关闭输入。停止后台任务、释放资源，一项清理失败仍尽力释放其余资源，必要时 Drop 兜底。运行时随后移除对象，即使关闭返回错误也不保留原对象继续使用；不得关闭其他对象。 |
| `get_port_no` | 可选；无 self 的关联函数，无需先初始化，返回 `MiresidianResult<Option<String>>`。参数默认来自 Input，可声明匹配条件、探测配置和超时；找到时返回后续连接所需地址，未找到时返回 None，执行失败时返回 Err。未实现时默认未找到。探测不登记实例，自行释放临时资源，不关闭现有对象；没有真实发现能力时可省略。 |

`GetPortNO` 的平台返回映射见 [固定查询与发现结果](c-abi.md#固定查询与发现结果)。相同对象的重复初始化复用不累计初始化引用；一次关闭会移除该对象。业务对象持有共享代理时只关闭自己的引用，底层物理连接的最后引用关闭规则见 [共享资源](shared-resources.md)。

### 实例模式、Config 组合主键与多通道调用

按需要查阅对应专题，不在本页重复定义运行时规则：

- 对象数量、Handle、框架 Config 布局、复用、关闭与多通道执行：[实例管理](instances.md)。
- 初始化参数上的 instance/lease 角色与组合身份：[Config 身份](config-identity.md)。
- 跨 DLL/进程共享连接与最后引用清理：[共享资源](shared-resources.md)。
- TB 平台的共享标记及通道文本协议：[平台调用契约](c-abi.md#实例生命周期与多通道调用)。

例如，外部调用 `config = ["COM3", "2500"]`、`input = ["令牌", "*IDN?"]` 时，以下两个方法按各自参数标注取值，而不是按方法名称限制通道。`address` 与 `timeout_ms` 分别取 `config[0]`；`token` 与 `command` 分别取 `input[0]`：

```rust
#[miresidian::operation]
fn init_device(
    #[miresidian::config("连接地址:COM3")] address: String,
    #[miresidian::input("初始化令牌")] token: String,
) -> MiresidianResult<(Self, String)> { # Ok((Self, format!("{address}:{token}"))) }

#[miresidian::operation("查询")]
fn query(
    &mut self,
    #[miresidian::input("命令")] command: String,
    #[miresidian::config("超时毫秒")] timeout_ms: u64,
) -> MiresidianResult<String> { # Ok(format!("{command}:{timeout_ms}")) }
```

## 可跨语言使用的类型

输入和输出 ABI 都是 UTF-8 文本。宏目前支持 `String`、`bool`、常用有符号/无符号整数、浮点数、`Option<T>` 和 `Vec<T>`。数组在平台侧使用 `|` 分隔，例如 `1|2|3`。`Vec<T>` 输出为一个 `|` 分隔的输出值；二元和三元元组可映射为多个输出值。

配置或输入标注中的 `名称:平台描述` 仅发布元数据，不用于运行时补值；包括路径在内的文本均按普通字符串处理。调用方可传裸值或 `名称:值`。

### 节点异常与租约边界

宏生成的节点调用由运行时统一捕获可展开 panic。构造函数返回实例前，失败或 panic 由函数内部的资源所有权、Drop 或显式回滚负责清理；实例返回后若业务输出编码或租约校验失败，框架会关闭并析构节点，再释放租约。业务操作 panic 后故障通道仅允许关闭，关闭后重新初始化才能恢复。关闭或析构 panic 不妨碍其余通道清理。节点方法仍应通过 `MiresidianResult` 返回预期错误，不能依赖 panic 处理业务失败。

Lease 的所有者初始化、引用关闭及故障规则统一见[共享资源](shared-resources.md#现有-lease-标签自动共享节点资源)。

## 数据编解码

Miresidian 的 `codec` 是根框架能力，负责强类型参数、平台字符串数组与原始字节之间的稳定转换。
节点只能声明 Rust 类型或调用 `decode_text_to_bytes`、`encode_bytes_to_text`、`transcode_text`；不得各自实现
HEX、Base64、字符编码或竖线数组语法。

本规范只覆盖平台文本与原始字节之间的转换。串口租约协议中的数据位、校验位等内部字段编码不属于本模块，也不会使用本模块的公开 API。

属性宏 crate 不实现这些规则。它只展开为对 `miresidian::codec::decode_value_with_definition` 与
`miresidian::codec::encode_value` 的调用；前者统一处理 `Config[]` 与 `Input[]`，因此每个
使用 `#[operation]` 的节点在运行时自动复用本规范。

### 数据格式

| 名称 | Rust 枚举 | 说明 |
| --- | --- | --- |
| `ASCII` | `ByteTextFormat::Ascii` | 严格 7 位 ASCII。它是 GBK 的子集。 |
| `GBK` | `ByteTextFormat::Gbk` | 明确的 GBK 中文编码。 |
| `UTF-8` | `ByteTextFormat::Utf8` | 标准 UTF-8。也接受 `UTF8`、`UTF_8` 别名；平台选项应使用不含连字符的名称。 |
| `Unicode` | `ByteTextFormat::Utf16Le` | 固定表示 UTF-16LE；也接受 `UTF-16LE`。 |
| `HEX` | `ByteTextFormat::Hex` | 原始字节的十六进制文本。 |
| `Base64` | `ByteTextFormat::Base64` | 原始字节的标准 Base64 文本。 |

不支持 `ANSI`。它在 C# 中通常指系统默认代码页，会随 Windows 区域设置变化，不能作为可重复的
跨语言测试契约。需要英文单字节文本时使用 `ASCII`；需要中文兼容编码时使用 `GBK`。

转换始终遵循“源格式文本 → 原始字节 → 目标格式文本”。例如：

```rust
use miresidian::{ByteTextFormat, transcode_text};

let hex = transcode_text("测试", ByteTextFormat::Gbk, ByteTextFormat::Hex)?;
assert_eq!(hex, "B2 E2 CA D4");
```

任何无法无损表示的转换都会返回 `MiresidianError::InvalidArgument`，不会以替换字符或 `?` 静默继续。
因此 GBK 可以读取和表达 ASCII，GBK 转 ASCII 遇到中文必定失败。

### 强类型参数

属性宏生成的参数解析通过 `NodeInput` 和 `NodeOutput` 完成。已支持：

- `String`、`bool`、`char`；
- 所有常用有符号、无符号整数和 `f32`、`f64`；
- `Option<T>`、一维 `Vec<T>` 与元组输出；
- `ByteTextFormat`；
- `Vec<u8>` 的 Base64 规范表示。

整数除十进制外还支持 `0x` 十六进制和 `0b` 二进制，例如 `0xFF`、`0b1010`。浮点数使用与区域
设置无关的小数点 `.`，并拒绝 `NaN` 和无穷值。

平台参数允许传入裸值或 `名称:值`，仍按数组位置取值，不按名称重排。0.22.0 起不从业务描述推导运行时默认值：缺参报错；已传入的数值空字符串或纯空白解析为整数 0、浮点 0.0，非空非法数值、越界和非有限值报错。Config 与 Input 使用相同规则。节点仍须按业务校验零值是否合法。

String 保留实际输入，空字符串仍为空字符串；Option<T> 显式空白为 None，缺参仍报错，即使标注 `备注:` 也不能省略。输出 None 为一个空字符串槽位，`()` 无输出，标准 Vec 为一个槽位，平坦元组按元素顺序输出。

完整候选文本如 `9600/19200` 不再取首项：数值解析报错，String 保留原文；具体实际值与显示值仍映射。平台实际传来的具体值按类型解析；节点描述的预填要求见[参数声明规范](#参数声明规范)。路径无内置专用参数类型，框架不补默认路径、不转换 `/`、`\` 或 `//`。框架 format 选择器、执行策略等明确声明的默认值不受此业务规则影响。默认值迁移见 [0.22.0 发布说明](releases/0.22.0.md)，后续类型规范化见 [0.23.0 发布说明](releases/0.23.0.md)。

### 选项实际值与显示值

候选项的实际值和显示值分别保持唯一；`-` 用作映射分隔符，不作为选项名称的一部分，UTF-8 选项可使用 `UTF8` 或 `UTF_8` 等受支持的别名。单项映射文本不作为实际值传入；具体显示值在解析前映射为实际值，数组逐项处理。

参数描述的候选项可写为 `实际值-显示值`，例如
`校验位:None-无校验/Odd-奇校验/Even-偶校验`。平台可传入 `Odd` 或 `奇校验`；属性宏会在
`NodeInput` 前把显示值规范化为实际值。数组值按 `|` 逐项规范化。完整的 `Odd-奇校验` 是描述文本，
不是业务输入；候选项实际值和显示值的唯一性由 DLL 项目保证。

### 一维数组

普通数组使用可逆竖线格式：

```text
alpha|beta|gamma
包含\|竖线|包含\\反斜杠
```

竖线和反斜杠必须分别写作 `\|`、`\\`。整型数组还支持递增范围展开，例如 `1-3|0x10` 等价于
`1|2|3|16`；单个范围最多展开 65536 项。

`Vec<u8>` 输出始终为 `base64:...`。输入可以使用同样的 Base64 形式，也可以使用普通整数数组，
例如 `1|2|0xFF`。

### 自定义类型

自定义业务类型按用途实现 `miresidian::NodeInput::parse_text(value, field)` 或 `NodeOutput::into_output(self)`，即可用作参数或返回值；枚举在业务模块解析实际值，未知值返回 InvalidArgument。若它还需要作为 `Vec<T>` 元素，应额外实现 `NodeCollectionElement`，明确其数组解析和格式化规则。框架不会隐式
将复杂对象数组编码为 JSON，避免在通用 ABI 中引入不可见的数据结构契约。

## 异步方法

`#[operation]` 支持 `async fn`。业务方法生成返回 `NodeFuture` 的原生桥，等待 I/O 时不占用同步业务阻塞线程；返回 Future 必须为 Send。
初始化、关闭和探测也允许 async，当前通过生命周期工作线程等待其 Future，和普通业务的原生 Future 调度应区分。
`&mut self` 的独占访问持续整个方法及其 await 期间；一个实例在等待 I/O 时仍不允许另一个请求插入。
宏同时保留同步桥，平台名称、参数来源、空白/缺参和输出编解码规则与同步方法一致。

业务可用 `CallContext::current()` 获取当前请求上下文，检查剩余时间或协作取消：

```rust,ignore
#[miresidian::operation]
async fn wait_ready(&mut self) -> miresidian::MiresidianResult<()> {
    let context = miresidian::CallContext::current();
    context.check()?;
    // 使用异步 I/O，并将 context.remaining() 传递给支持超时的操作。
    // 或等待 context.cancelled().await 后执行必要回滚，再返回 context.check()。
    Ok(())
}
```

同步方法在阻塞池运行，取消不会杀死线程；应检查上下文或使用自身 I/O 超时。
框架不会通过丢弃执行中的业务 Future 提前释放实例。方法若不检查上下文，取消后仍可能成功完成。
业务方法不要同步重入同一实例的运行时请求，否则会等待自己持有的实例执行权。

Broadcast 的方法仍通过相同 operation 标注声明；0.16.0 运行时固定调用通道1一次后复制输出，规则见[广播规范](instances.md#broadcast-的执行源与输出规则0160)。该广播规则由运行时执行，节点沿用相同的 operation 声明形式。


## format feature：独立的格式转换增强（0.19.0 起）

默认类型解析始终可用。可选 format feature 提供普通业务 Input/Output 的显式格式转换，实现位于 `features/format/`；完整标注、转换矩阵、槽位顺序和批量示例见 [format 说明](../features/format/README.md)。

`#[miresidian::input("数据", format(utf8, hex, selector = "数据格式"))] data: Vec<u8>`（旧 `format(formats = [utf8, hex], selector = "数据格式")` 等价保留） 生成数据和格式两个相邻 Input；第一项为默认。单项 `format(hex)` 与旧 `format(formats = [hex])` 都不生成选择输入。输出标签可采用同样声明，其选择输入追加在方法输入之后。多输出可逐项标注，不能混用原有多名称标注。

### 可选：与 batch 组合

format 负责单条表示转换，batch 负责按类型展开和调用，两者 feature 独立。字符串、布尔和字符可以只标 batch，不需要 format 放行；需要编码转换时才同时标注。数据与格式选择各自允许单值或列表，长度一广播、其余等长；batch 方法的输出格式也可逐条选择，输入布局不变。固定单编码仍不接受 selector，也不增加输入槽位。

例如原参数 String 的数据 `A|42|Qw==` 与格式 `UTF8|HEX|Base64` 依次得到 A、B、C。编码记录解码后不重新按竖线或整数范围拆分。完整转义、空记录、多列与输出规则见 [format](../features/format/README.md)；方法仍处理单条原类型参数。

### batch 的类型解析（独立于 format）

普通 batch 使用原类型的 NodeInput、NodeCollectionElement、Clone，允许数值、String、bool、char 及提供对应契约的自定义类型。类型别名、完整路径同样生效；不存在宏数值白名单。

整数保留单值、列表、非负递增范围及 `1-3|5|8-10` 混合形式；浮点支持逐项列表、负值及科学计数法，不推断范围。字符串的 `1-3` 保持一个文本项，布尔复用默认解析规则。单值广播、按位置配对、顺序、首错停止及逐槽聚合见 [batch](../features/batch/README.md)。空文本是一条空记录，由原类型校验，普通 Vec 的空集合规则不变。

新增增强能力自 0.19.0 统一使用 format 名称；0.18.x 的 codec feature/标签需在主动迁移时更新，默认 `miresidian::codec` API 不变。

## 配置规范文本

根运行时按初始化参数的原 Rust 类型生成归一化回调，实例配置比较和租约参数编码共用该回调。内置数值的空白、显式零和等价进制表示形成同一规范文本；类型别名遵循同一 trait。String 与自定义类型默认保留文本，自定义类型可通过 NodeInput::normalize_text 声明自己的纯归一化规则。Option 保留 None 与 Some(0) 区别，Vec 按自己的集合语法规范化。

主键/Handle 判空先于类型归一化，不能将空身份转换为零对象；多实例业务调用和关闭不因无关非主键值改变已保存配置。数组选项映射先识别完整转义元素再匹配显示值，不对字面竖线后的片段单独替换。
