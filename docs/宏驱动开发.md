# 节点开发与数据编解码

[文档中心](README.md) · [架构总览](architecture.md)

本文统一说明节点声明、宏标注、跨语言类型和数据编解码规则。

**章节导航：[职责边界](#职责边界) · [声明方式](#声明方式) · [可用类型](#可跨语言使用的类型) · [数据编解码](#数据编解码)**

Miresidian 的驱动公开契约由方法签名和可选标注声明，驱动作者不得手写 `GetFunctions`、`GetInitConfig`、操作字符串分发或 C ABI 入口。结构体上的 `#[miresidian::node]` 声明节点，方法上的 `#[miresidian::operation]` 独立读取签名并生成平台契约；框架汇总注册项并生成统一入口。

参数标注中的平台描述文本必须原样透传；实际值与显示值的顺序等固定规则见[平台调用契约](c-abi.md#平台调用契约)。

描述中实际值与显示值相同时只写一次，如 `数据格式:ASCII/GBK/UTF-8`；只有二者不同才写为
`实际值-显示值`。物理量单位写为 `名称/单位:默认值`，如 `读取超时/ms:1000`；“字节数”等
计数保持普通 `名称:默认值` 形式。

## 职责边界

一个可发布节点由三个层次协作完成：

| 层次 | 责任 | 不应承担的责任 |
| --- | --- | --- |
| `miresidian` 运行时 | 生命周期、文本类型转换、调用契约、C ABI 支撑 | 任何特定通信库或设备协议 |
| `miresidian_macro` | 读取标注，生成描述信息、`DeviceNode` 调度和 DLL 导出 | 具体设备通信、端口或协议状态 |
| `constellation/<节点>` | 节点状态、通信实现、方法标注和该节点测试 | 手写平台函数列表、字符串分发或 ABI 导出 |

宏实现位于 `macro/src/`。`node.rs + node/` 负责结构体声明、节点绑定及 C ABI；
`operation.rs + operation/` 负责方法解析、自动命名、参数描述和调用包装。方法通过内部
inventory 注册表汇总，不扫描源码、不依赖宏展开顺序，也不要求额外的 impl 标记。

宏只负责编译期语法检查与代码生成，不实现运行时数据转换。生成的参数调度统一调用
`miresidian::codec::decode_value_with_definition`，返回值统一调用
`miresidian::codec::encode_value`。`decode_value` 对 Config 与 Input 使用同一套规则，因此数值进制、数组转义、Base64 和文本编码规则只
维护在根框架的 `codec` 中，节点与宏项目均不得复制实现。

## 声明方式

```rust
#[miresidian::node("示例设备")]
pub struct ExampleNode {
    // 驱动状态与通信对象。
}

impl ExampleNode {
    #[miresidian::operation]
    fn init_device(
        address: String, port: u16,
    ) -> MiresidianResult<(Self, String)> {
        # let _ = (address, port);
        # Ok((Self {}, "已连接".to_owned()))
    }

    #[miresidian::operation]
    fn close_device(&mut self) -> MiresidianResult<()> {
        Ok(())
    }

    #[miresidian::operation]
    fn query(
        &mut self,
        request: String,
        maximum_bytes: usize,
    ) -> MiresidianResult<String> {
        # let _ = (request, maximum_bytes);
        # Ok(String::new())
    }
}
```

`node` 的参数为 DLL 的平台展示名称。方法级 `operation` 识别以下约定方法：

| Rust 方法 | 平台操作 | 标注规则 |
| --- | --- | --- |
| `init_device` | `InitDevice` | 未标注参数自动从 Config 读取；可用 `input` 将单个参数改为从 Input 读取。 |
| `close_device` | `CloseDevice` | 未标注参数自动从 Input 读取；通常没有参数。 |
| （框架提供） | `CloseAllDevices` | 不需要节点方法；无参数，关闭并释放当前运行时的全部通道。 |
| `get_port_no` | `GetPortNO` | 可选；未标注参数自动从 Input 读取，且无需先初始化。 |
| 任意方法 | 自动 PascalCase 或标注名称 | 使用 `operation` 标记；未标注参数自动从 Input 读取。`config`、`input` 与 `output` 可分别指定参数通道、平台名称及默认值、输出名称。 |

宏自动生成固定的 `GetFunctions` 与 `GetInitConfig`，以及每个节点 DLL 的调用入口 `miresidian_invoke`、`miresidian_invoke_with` 和 `miresidian_abi_version`。入口使用 JSON 字符串数组与固定 JSON 响应对象，见 [C ABI](c-abi.md)。稳定 Rust 不允许把属性直接写在 `->` 后的返回类型上，因此 `output` 放在方法上、紧邻 `operation`。

### 标注规则

- `#[miresidian::node("名称")]` 必须标注在节点结构体上，名称用于平台显示和发布目录。可选 `platforms(AdapterType, ...)` 会把一个或多个实现 `PlatformAdapter + Default` 的适配器编译进 DLL，例如 `#[miresidian::node("名称", platforms(MyPlatformAdapter))]`。框架始终保留 TB 兼容适配器。
- C ABI 首次调用时按节点声明的适配器注册表创建运行时；外部方可通过 `miresidian_invoke` 的 `InitDevice` 保留 `平台适配` Config 选择 id，也可通过 `miresidian_invoke_with` 显式传入平台枚举值；后者不发布也不接受该 Config。
- 移除 `node_impl`。节点及其平台方法保留在同一模块，一个模块声明一个具体节点，允许拆为多个固有 `impl`；其他模块的普通辅助类型不受影响。节点结构体与平台方法不能带泛型参数，也不能把 operation 用于 trait impl。
- `init_device` 与 `close_device` 必须标注 `#[miresidian::operation]`；缺失对应桥接会在编译期报错。初始化是无 self 的关联函数，返回 `MiresidianResult<Self>` 或 `MiresidianResult<(Self, T)>`；关闭及普通业务方法仍以 `&mut self` 为接收者。节点无需实现 `Default`，框架也不自动生成它。
- 可选的 `get_port_no` 同样标注 operation，使用无 self 的关联函数；探测过程中取得的临时资源由函数自行回收，不创建或关闭节点实例。
- `#[miresidian::operation]` 不带参数时使用方法名自动转换后的平台名称；
  `#[miresidian::operation("名称")]` 使用显式名称。多通道执行由节点级 `instances(...)` 声明；只有 selectable 才在 `InitDevice` 发布执行方式配置；驱动方法无需通过 `operation` 标注选择顺序、并行或广播。
- 未标注参数使用自动来源：`init_device` 默认从 Config 读取，其他固定入口与 `operation`
  默认从 Input 读取。`#[miresidian::config]` 与 `#[miresidian::input]` 可标注在任意平台方法的
  非 `self` 参数上，并逐参数覆盖该默认来源；两者都可写为 `("名称")` 或
  `("名称:默认值")`。同一参数不能同时标注两者。
- `#[miresidian::output("名称")]` 标注在方法上。一个标注可给出多个逗号分隔的输出名，
  数量应与返回值可展开的输出数量一致。

未带字符串的 `operation` 会把 Rust 方法名转换为测试平台的 PascalCase：`read_text` 变为 `ReadText`，`read_tcp_ip` 变为 `ReadTcpIp`。`init_device`、`close_device` 与 `get_port_no` 是固定平台入口，分别固定映射为 `InitDevice`、`CloseDevice`、`GetPortNO`；`CloseAllDevices` 由运行时固定提供，不对应节点方法；其中 `GetPortNO` 是唯一的缩写特例。

未使用 `config` 或 `input` 标注时，平台参数名同样自动转为 PascalCase，例如 `port_name` 为 `PortName`、`port_no` 为 `PortNo`。缺少 `output` 标注时，标量、字符串与数组返回值使用“返回值”；二元或三元元组按顺序自动生成“返回值1”“返回值2”“返回值3”；`MiresidianResult<()>` 自动生成空输出。显式 `output` 的名称数量必须与返回值输出数量完全一致，否则编译失败。

### 初始化输出与方法注册

初始化返回的 `Self` 只由运行时保存，不是平台输出。返回 `MiresidianResult<Self>` 时无业务输出；返回 `MiresidianResult<(Self, T)>` 时，仅 T 按原有规则编码和发布 output 名称。多个业务输出使用 `T = (A, B, ...)`，例如返回 `(Self, (String, u32))` 时 output 仍声明两个名称。

config、input、output 的写法、参数来源、名称、默认值、输出数量和编解码规则保持不变；output 位于 operation 前后均可。初始化函数因取消 self，不会跳过第一个业务参数。

业务方法通过内部 inventory 注册项汇总，按照 `(源码文件、行、列)` 排序，同一文件保持声明顺序；cfg 或 cfg_attr 禁用的方法不会遗留注册。运行时在查询或执行前拒绝重复的平台名称和框架保留名称，不任意选取一个处理器。

[inventory 0.3.24](https://github.com/dtolnay/inventory) 使用 MIT OR Apache-2.0，兼容 MSRV 1.89，注册后端支持项目所需的 Linux/Windows；采用成熟库封装链接保留和元数据注册，避免手写平台段布局。加载时只注册元数据与函数指针，不打开设备、获取租约或调用业务。第三方接口仅通过隐藏宏支持项使用，不是节点的稳定公共 API。发布时须验证 x64/x86 DLL 的实际链接、加载与注册保留，交叉检查不能代替加载验证。

### 实例模式、Config[0] 主键与多通道调用

默认节点使用单实例，异配置初始化替换旧对象；开启 feature 本身不改变默认节点。需要多实例或多通道输入时，使用与 feature 同名的 `instances(...)`，完整声明示例与规则见[实例管理](instances.md)。

新节点项目必须将业务对象主键放在初始化第一个 Config 参数（下标 0）。multiple/config 仅以规范化后的 Config[0] 识别对象，同主键配置不一致时报错；空 Config[0] 在补默认值之前跳过初始化。没有业务 Config 的 multiple/config 声明编译失败；框架不会根据参数名称猜测主键。

multiple/handle 自动在业务 Config 后追加 Handle，框架在所有调用路径提取并剥离，节点业务参数索引不变。相同 Handle 配置一致时复用，不同 Handle 不按配置合并；空 Handle 初始化跳过。Config[0]、Handle、租约、平台和执行方式的布局由元数据及解析共用。

实例策略只决定对象数量、关联键和执行方式。平台各通道输入使用一次 Config 定位的同一对象；TB 继续使用 Input 首项 `共享` 与逗号协议。框架规范名称是多通道，执行策略为 sequential/parallel/broadcast/selectable。固定方式不追加参数，selectable 的方式保存在对应对象上。

例如，外部调用 `config = ["COM3", "2500"]`、`input = ["令牌", "*IDN?"]` 时，以下两个方法按各自参数标注取值，而不是按方法名称限制通道。`address` 与 `timeout_ms` 分别取 `config[0]`；`token` 与 `command` 分别取 `input[0]`：

```rust
#[miresidian::operation]
fn init_device(
    #[miresidian::config("设备地址")] address: String,
    #[miresidian::input("初始化令牌")] token: String,
) -> MiresidianResult<(Self, String)> { # Ok((Self, format!("{address}:{token}"))) }

#[miresidian::operation("查询")]
fn query(
    &mut self,
    #[miresidian::input("命令")] command: String,
    #[miresidian::config("超时毫秒")] timeout_ms: u64,
) -> MiresidianResult<String> { # Ok(format!("{command}:{timeout_ms}")) }
```

## 可跨语言使用的类型

输入和输出 ABI 都是 UTF-8 文本。宏目前支持 `String`、`bool`、常用有符号/无符号整数、浮点数、`Option<T>` 和 `Vec<T>`。数组在平台侧使用 `|` 分隔，例如 `1|2|3`。`Vec<T>` 输出为一个 `|` 分隔的输出值；二元和三元元组可映射为多个输出值。

配置或输入标注中的 `名称:默认值` 会同时生成平台元数据，并用于缺失或空白参数的默认值解析。调用方仍可传裸值或 `名称:值`。

### 节点异常与租约边界

宏生成的节点调用由运行时统一捕获可展开 panic。构造函数返回实例前，失败或 panic 由函数内部的资源所有权、Drop 或显式回滚负责清理；实例返回后若业务输出编码或租约校验失败，框架会关闭并析构节点，再释放租约。业务操作 panic 后故障通道仅允许关闭，关闭后重新初始化才能恢复。关闭或析构 panic 不妨碍其余通道清理。节点方法仍应通过 `MiresidianResult` 返回预期错误，不能依赖 panic 处理业务失败。

租约声明只协调资源配置。v2 由客户端持有跨进程配置文件锁，并在每次操作前验证会话；它不提供物理句柄共享或跨进程事务互斥。节点不应根据 `First/Shared` 推断设备可否重复打开。升级与部署约束见 [租约说明](../lease/README.md)。

## 数据编解码

Miresidian 的 `codec` 是根框架能力，负责强类型参数、平台字符串数组与原始字节之间的稳定转换。
设备节点只能声明 Rust 类型或调用 `decode_text_to_bytes`、`encode_bytes_to_text`、`transcode_text`；不得各自实现
HEX、Base64、字符编码或竖线数组语法。

本规范只覆盖平台文本与原始字节之间的转换。串口租约协议中的数据位、校验位等内部字段编码不属于本模块，也不会使用本模块的公开 API。

属性宏 crate 不实现这些规则。它只展开为对 `miresidian::codec::decode_value_with_definition` 与
`miresidian::codec::encode_value` 的调用；前者统一处理 `Config[]` 与 `Input[]`，因此每个
使用 `#[operation]` 的节点在运行时自动复用本规范。

### 数据格式

| 名称 | Rust 枚举 | 说明 |
| --- | --- | --- |
| `ASCII` | `ByteTextFormat::Ascii` | 严格 7 位 ASCII。它是 GBK 的子集。 |
| `GBK` | `ByteTextFormat::Gbk` | 明确的 GBK 中文编码。 |
| `UTF-8` | `ByteTextFormat::Utf8` | 标准 UTF-8。也接受 `UTF8` 别名。 |
| `Unicode` | `ByteTextFormat::Utf16Le` | 固定表示 UTF-16LE；也接受 `UTF-16LE`。 |
| `HEX` | `ByteTextFormat::Hex` | 原始字节的十六进制文本。 |
| `Base64` | `ByteTextFormat::Base64` | 原始字节的标准 Base64 文本。 |

不支持 `ANSI`。它在 C# 中通常指系统默认代码页，会随 Windows 区域设置变化，不能作为可重复的
跨语言测试契约。需要英文单字节文本时使用 `ASCII`；需要中文兼容编码时使用 `GBK`。

转换始终遵循“源格式文本 → 原始字节 → 目标格式文本”。例如：

```rust
use miresidian::{ByteTextFormat, transcode_text};

let hex = transcode_text("测试", ByteTextFormat::Gbk, ByteTextFormat::Hex)?;
assert_eq!(hex, "B2 E2 CA D4");
```

任何无法无损表示的转换都会返回 `MiresidianError::InvalidArgument`，不会以替换字符或 `?` 静默继续。
因此 GBK 可以读取和表达 ASCII，GBK 转 ASCII 遇到中文必定失败。

### 强类型参数

属性宏生成的参数解析通过 `DeviceInput` 和 `DeviceOutput` 完成。已支持：

- `String`、`bool`、`char`；
- 所有常用有符号、无符号整数和 `f32`、`f64`；
- `Option<T>`、一维 `Vec<T>` 与元组输出；
- `ByteTextFormat`；
- `Vec<u8>` 的 Base64 规范表示。

整数除十进制外还支持 `0x` 十六进制和 `0b` 二进制，例如 `0xFF`、`0b1010`。浮点数使用与区域
设置无关的小数点 `.`，并拒绝 `NaN` 和无穷值。

平台参数允许传入裸值或 `名称:值`。当属性声明了默认值时，缺失或空白参数会采用默认值；这对
Config 与 Input 通道完全一致。

### 选项实际值与显示值

参数描述的候选项可写为 `实际值-显示值`，例如
`校验位:None-无校验/Odd-奇校验/Even-偶校验`。平台可传入 `Odd` 或 `奇校验`；属性宏会在
`DeviceInput` 前把显示值规范化为实际值。数组值按 `|` 逐项规范化。完整的 `Odd-奇校验` 是描述文本，
不是业务输入；候选项实际值和显示值的唯一性由 DLL 项目保证。

### 一维数组

普通数组使用可逆竖线格式：

```text
alpha|beta|gamma
包含\|竖线|包含\\反斜杠
```

竖线和反斜杠必须分别写作 `\|`、`\\`。整型数组还支持递增范围展开，例如 `1-3|0x10` 等价于
`1|2|3|16`；单个范围最多展开 65536 项。

`Vec<u8>` 输出始终为 `base64:...`。输入可以使用同样的 Base64 形式，也可以使用普通整数数组，
例如 `1|2|0xFF`。

### 自定义类型

自定义业务类型实现 `DeviceInput` 与 `DeviceOutput` 后即可用作节点参数和返回值。若它还需要作为
`Vec<T>` 元素，应额外实现 `DeviceCollectionElement`，明确其数组解析和格式化规则。框架不会隐式
将复杂对象数组编码为 JSON，避免在通用 ABI 中引入不可见的数据结构契约。

## 异步方法

`#[operation]` 支持 `async fn`。业务方法生成返回 `NodeFuture` 的原生桥，等待 I/O 时不占用同步业务阻塞线程；返回 Future 必须为 Send。
初始化、关闭和探测也允许 async，当前通过生命周期工作线程等待其 Future，和普通业务的原生 Future 调度应区分。
`&mut self` 的独占访问持续整个方法及其 await 期间；一个实例在等待 I/O 时仍不允许另一个请求插入。
宏同时保留同步桥，平台名称、参数来源、默认值和输出编解码规则与同步方法一致。

业务可用 `CallContext::current()` 获取当前请求上下文，检查剩余时间或协作取消：

```rust,ignore
#[miresidian::operation]
async fn wait_ready(&mut self) -> miresidian::MiresidianResult<()> {
    let context = miresidian::CallContext::current();
    context.check()?;
    // 使用异步 I/O，并将 context.remaining() 传递给支持超时的操作。
    // 或等待 context.cancelled().await 后执行必要回滚，再返回 context.check()。
    Ok(())
}
```

同步方法在阻塞池运行，取消不会杀死线程；应检查上下文或使用自身 I/O 超时。
框架不会通过丢弃执行中的业务 Future 提前释放实例。方法若不检查上下文，取消后仍可能成功完成。
业务方法不要同步重入同一实例的运行时请求，否则会等待自己持有的实例执行权。
