# Miresidian 0.24.0

## 中文

初始化 Config 现在可用嵌套 instance(key/ignore)、lease(key/ignore) 声明相互独立的业务对象身份与资源身份。不新增独立参数属性，整体策略仍放在 node 的 instances/lease 子配置。

multiple/config 未标记时改为全部业务 Config 组成实例键；有显式 key 时仅取 key，只有 ignore 时取其余参数。要保留 0.23.x 的 Config[0] 路由，在原第一个 Config 上添加 instance(key)。任一选中键原始值为空则跳过初始化；同键但完整初始化配置不同仍报冲突。

租约新声明必须显式选择至少一个 lease(key)，其余 Config 自动参与兼容性比较，lease(ignore) 排除；不要把波特率并入物理资源身份来规避冲突。旧 resource/configuration 字段列表保留，不能与参数租约角色混用。单字段保留规范文本，多个字段采用带版本前缀的长度边界编码；单字段不得占用 miresidian:tuple:v1: 保留前缀。跨提供者须统一值顺序、配置字段名/顺序及归一化规则。租约仍不提供物理连接共享。

版本：框架 0.24.0、宏 0.22.0、lease 0.16.0、instances 0.16.5（仅随包说明修正）；其余 crate/工具、C ABI v7、配置租约 v2、资源代理 v1 与 MSRV 1.89 不变。独立节点只能在所需版本已发布到 crates.io 后升级精确依赖；本任务不修改相邻节点或发布 registry。

完整契约、TCP/串口组合及迁移见 [Config 组合身份与租约声明](../config-identity.md)。

验证：默认/全特性工作区、角色组合与独立 feature、两个 C ABI 入口、编译诊断、严格 Clippy/Rustdoc、Rust 1.89、Release 构建及完整 skill 同步检查通过。测试为 Linux 模拟和进程内 ABI；Windows 原生加载及真实设备未实测。

## English

Nested init Config roles select independent instance and lease identities. Policies remain on node; no standalone role attributes are introduced.

Config-bound instances now use all business Config by default. Explicit keys select only those fields; ignore-only annotations exclude fields. To preserve 0.23.x routing, mark the original first Config with instance(key). An empty selected raw identity skips initialization. Matching keys with different complete initialization settings remain a conflict.

New lease declarations require explicit resource keys. Other fields become compatibility settings unless marked lease(ignore). Legacy field lists remain supported but cannot be mixed with parameter lease roles. Ordinary single-field keys and existing configuration bytes are preserved; composite keys use a reserved versioned, length-delimited encoding. Resource coordination does not provide physical connection sharing.

Versions: runtime 0.24.0, macros 0.22.0, lease 0.16.0, instances 0.16.5 (shipped explanation correction only). Other components/tools, C ABI v7, lease v2, resource v1 and Rust 1.89 are unchanged. Source commits and tags do not imply registry publication. Independent nodes retain published exact dependencies until adopting an available release.

Validation covers default/all-feature workspaces, joint and isolated roles, both C ABI entries, compile diagnostics, strict Clippy/Rustdoc, Rust 1.89, Release builds and complete skill synchronization. Evidence is Linux simulation and in-process ABI; native Windows loading and real devices were not tested.
