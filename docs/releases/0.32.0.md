# 0.32.0 GetPortNO 原因输出

节点未实现 get_port_no 时，平台固定返回 `["0", "当前未实现端口发现能力"]`；已实现但返回 None 时为 `["0", "未找到匹配设备"]`；Some(address) 仍为 `["1", address]`。NotSupported 的非空说明作为未找到原因，空白说明补默认未实现文本。其他错误和 panic 保持错误响应，不混入正常输出。

正常未找到保持 status=0、code=OK、message=""。GetFunctions 将第二项描述为“端口号或原因”，宿主按 output[0] 判断第二项含义。无需先初始化节点。

Option<String> 返回类型和同步/async 方法签名不变，不新增结果类型。直接 Rust Node 默认探测由 Ok(None) 改为 NotSupported；平台入口会将它转换成上述正常结果。根 0.32.0 / macro 0.28.0 同步精确依赖与锁文件；C ABI v10 的签名、JSON、输出数和内存契约，以及其他组件保持。本次仅本地源码候选，未推送、未发布。

English: Unimplemented discovery returns exactly `["0", "当前未实现端口发现能力"]`; None receives a generic miss reason and Some retains its address. NotSupported carries a normal miss reason, while other errors remain errors. Option<String> signatures and ABI v10 transport are unchanged. Direct default Node calls now report NotSupported.
