# Miresidian 0.27.0：运行时选择平台 / Runtime platform selection

日期：2026-11-10。源码候选：框架 0.27.0、ABI crate 0.16.0 / C ABI v9、宏 0.23.2（仅随包说明补丁）。本次仅本地提交和不可移动标签，不推送或发布。其他组件、工具、配置租约/资源代理 v2 及 Rust MSRV 1.89 保持。

## 调用流程

两个带平台入口现在将 `0`（`MIRESIDIAN_PLATFORM_RUNTIME_SELECT`）路由至既有 Config 平台选择流程。完整请求省略 platform 与传 0 等价；非零继续显式指定已注册的平台适配器。0 表示流程入口，不是具体适配器，不弹出 UI。宿主执行指定的操作并负责呈现查询结果。

对于没有业务初始化 Config、Handle、租约选择或执行方式项的节点，可依次调用：

```json
{"platform":0,"function":"GetInitConfig"}
{"platform":0,"function":"InitDevice","config":["平台适配:tb_lv_test_platform"]}
{"platform":0,"function":"GetFunctions"}
{"platform":0,"function":"CloseDevice"}
```

第一步 `output` 中的 `平台适配:<id...>` 是可选项来源；宿主让用户从当前 DLL 已注册的 id 中选择，再构造第二步。上例只有 TB 平台时选它；注册自定义适配器的 DLL 会发布对应标识。实际节点的业务 Config 和其他框架项须按本节点 GetInitConfig 发布的完整顺序传入，不能直接照抄无业务 Config 的例子。

分参入口同样可查询：

```c
const char *result_json = miresidian_invoke_with(
    MIRESIDIAN_PLATFORM_RUNTIME_SELECT, "GetInitConfig", "[]", "[]");
/* 立即复制 result_json，解析 output 中的平台选项，并由宿主呈现给用户。 */
```

`InitDevice` 未传平台选择项时保持既有默认平台行为；成功选型后，后续 0/省略平台调用使用运行时已选适配器。普通业务调用按节点原有 Config 定位，不需要重复平台选择器。已有实例存活期间切换被拒绝，全部关闭后可重新选择。非零路径的初始化元数据不发布也不接受平台选择器；2..65535 保留编号仍返回 INVALID_PLATFORM_ID，合法但未注册的编号仍返回 UNKNOWN_PLATFORM_ADAPTER。

## 迁移与发行边界

ABI v8 对 0 返回 INVALID_PLATFORM_ID；ABI v9 才支持上述流程。宿主读取 `miresidian_abi_version()`，评估兼容后将 9 加入支持版本集合。函数签名、调用约定、JSON 四字段及线程响应缓存所有权保持，版本查询不替换响应；仍须在下一次同线程调用前复制响应，不得修改或释放。

`Platform::from_abi(0)` 仍返回 None：它用于解析具体适配器，入口在其之前处理 0 的选择流程。框架及宏不会将 0 注册成平台。宏沿用已有转发代码，新标注或手写导出均不需要。

上述候选尚未发布，不能将 `=0.27.0` 当作可安装的 registry 依赖。独立 Node 和烟测夹具仅在实际所需版本正式可用后升级精确依赖并重建；本任务不改它们的依赖或锁文件。源码、标签、crates.io 发布和 docs.rs 可访问性分开核对；旧版资料与安装示例不证明 v9 能力。现有 Pack 模板支持范围按其[实际版本手册](../../tools/miresidian-pack/README.md#最小模板)核对，不能据本次框架变化推断工具已支持 v9。

## English

Source candidates: framework 0.27.0, ABI crate 0.16.0 / C ABI v9, and macro 0.23.2 for bundled guidance only. No push, registry publication or independent-node upgrade is included.

Platform zero in either platform-taking entry follows Config selection, just like an omitted JSON platform. Query GetInitConfig/GetFunctions, let the host show the registered platform identifiers, then pass the chosen identifier in InitDevice Config at the published position. Later zero calls follow the active adapter. The example above assumes a node with no business or other framework configuration fields; actual callers must follow their complete metadata. Zero does not open a dialog or substitute an operation name. Missing selection retains the existing default. Switching with live instances is rejected; close all instances before choosing again. Nonzero selection rules remain unchanged.

ABI v8 rejects zero. Review compatibility and accept ABI 9 before using this route. Function signatures, JSON response fields and thread-local ownership remain unchanged; copy responses immediately and never free them. Concrete adapter parsing still rejects zero because the ABI entry handles this routing value first. Adopt candidate versions in independent nodes only after actual registry publication; source tags do not establish registry or docs.rs availability.
