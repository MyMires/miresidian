# 0.34.0：实例简写与 encoding 名称迁移

本页对应本地源码候选：框架 0.34.0、macro 0.30.0、miresidian_encoding 0.5.0。尚未推送或发布；源码、标签、crates.io 与 docs.rs 分别核实，不能将候选当作可直接安装版本。独立 Node 保留其已发布精确依赖，禁止 path/git/patch 绕过发行。

## 名称映射

| 原名称 | 新名称 |
| --- | --- |
| Cargo feature format | encoding |
| 宏分组 format(...) | encoding(...) |
| miresidian_format / features/format/ | miresidian_encoding / features/encoding/ |
| miresidian::format | miresidian::encoding |
| FormatInput / FormatOutput | EncodingInput / EncodingOutput |
| from_format_bytes / into_format_bytes | from_encoding_bytes / into_encoding_bytes |
| decode_formatted / decode_formatted_batch / encode_formatted | decode_encoded / decode_encoded_batch / encode_encoded |
| select_format / select_format_value | select_encoding / select_encoding_value |

旧入口不保留别名。原有具名字段 formats 和 selector 保持，在 encoding 分组下继续使用。基础 codec、ByteTextFormat、parse_byte_text_format、decode_text_to_bytes/encode_bytes_to_text/transcode_text，以及 Rust format! 和平台 format_parameter 不属于重命名范围。

## 实例关联

```rust,ignore
#[miresidian::node("设备", instance(multiple, selectable(sequential)))]
// multiple 默认 Config；以下也合法：
// instance(multiple(config))
// instance(multiple(handle), parallel)
```

裸 multiple 与 multiple(config) 都归一为多实例 Config 关联；未写执行方式时固定 sequential。旧 multiple, config/handle 及合法排列继续支持，完整长写的 mode/binding/execution 仍按原规则必填。

multiple()、未知/多个关联、重复模式或关联、single 带关联、同组长短混用均编译报错。默认 Config 不改变 instance(key/ignore)、归一化、空身份、配置冲突、复用或关闭规则。

single 仍支持 sequential、parallel、broadcast 及 selectable(default)，省略 instance 仍禁用多通道。一次多通道请求定位一个对象，同对象完整业务调用仍互斥，包括 async 等待期间；parallel 不承诺同对象业务重叠。

## 编码选择器

```rust,ignore
#[miresidian::input("发送数据:平台描述", encoding(utf8, hex))]
// 自动生成“发送数据格式”
#[miresidian::output("结果", encoding("输出编码", utf8, hex))]
// 显式使用“输出编码”
#[miresidian::input("原始字节", batch, encoding(hex))]
// 固定 HEX，无选择器或额外 Input
```

多编码未命名时，用外层参数显示名在首个冒号前的部分 trim 后追加“格式”。encoding("名称", utf8, hex) 使用字符串首项命名，encoding(utf8, hex, selector = "名称") 和 encoding(formats = [utf8, hex], selector = "名称") 继续支持；未命名长写也自动生成名称。

第一项仍为默认编码，缺失/空白选择和 batch 空格式项沿用默认。输入选择器紧随对应数据，输出选择器按输出声明顺序追加到所有方法 Input 末尾。自动和显式同名声明生成等价元数据与调用布局。batch 仍按原类型与单值广播/等长规则组合，不重新解释解码后的字节。

单编码禁止选择器名称；字符串名称必须在首项且至少有两种合法编码。空白名称、包含 : / |、重复编码、未知编码、重复命名或混合位置列表与 formats 数组均拒绝。方法内业务 Input 与所有格式选择器名称必须唯一，冲突时显式指定不同名称，不自动编号。自动名称随外层显示名变化，需要固定平台契约时显式命名。
