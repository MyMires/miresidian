# 0.30.2 Windows 租约服务启动修复

GitHub Windows Rust 1.89 检查暴露首次并发获取租约时的命名管道竞争。依赖使用 FIRST_PIPE_INSTANCE 创建监听器，同名服务已存在时 Windows 返回 ERROR_ACCESS_DENIED (5)；原先仅按 Unix AddrInUse 处理，导致初始化偶发失败。

根框架 0.30.2 精确依赖 lease 0.17.4。创建遇到该竞争错误后，沿用有界连接已有服务流程；只有实际连接成功才返回成功，重试耗尽返回原创建错误。其他创建错误立即返回，不放宽管道权限。已有失效会话不重连、不重放。

公开 Rust API、业务参数、C ABI v10、配置租约及资源代理协议 v2 保持。采用包含修复的已发布版本后重新构建相关 DLL，无需修改业务标签或宿主调用。其他组件不跟升。验收结果见[任务方案](../../plans/2026-11-11-enum-display-options.md)。

## English

Framework 0.30.2 depends exactly on lease 0.17.4. Competing Windows FIRST_PIPE_INSTANCE listeners return native error 5, which now triggers bounded attempts to connect to the winning service. Success requires a real connection; exhaustion preserves the original creation error. Other errors still fail immediately. Invalidated sessions never reconnect or replay. Rebuild participating DLLs using the published fix; public APIs, parameters, C ABI v10 and both protocols v2 are unchanged.
