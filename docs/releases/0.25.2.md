# 0.25.2：Node DLL 主入口与依赖目录指导

本次仅发布根框架 0.25.2，将已确认的 Node DLL 目录规范纳入正式发行包；运行时代码、宏及其版本、内部精确依赖、其他 crate/工具、C ABI v7、配置租约 v2、资源代理 v2 和 MSRV 1.89 均保持不变。

## 交付方式

每个节点对应架构目录（例如 `dist/<节点>/windows-x64/`）的顶层只放一个供用户调用的 Node DLL。随附的第三方及辅助运行时 DLL 统一放在该目录下的 `dependencies/`，调用说明明确主入口文件名、适用位数和依赖目录用途。没有此类依赖时无需创建空目录，也不要求新增 `references/`。头文件及发布根目录中的说明、CHANGELOG、manifest 沿用原有位置。

这一要求帮助用户辨识主入口。实际调整已有交付物时，仍须按实际加载方式处理依赖解析，并取得目标平台的加载调用证据；Windows 不会仅因目录叫 `dependencies/` 就自动搜索它。本次不改变 Pack 的收集行为或宿主/Node 的加载代码。

完整示例见[开发与维护规范](../coding-standards.md#6-注释与文档)，节点开发入口见[节点手册](../宏驱动开发.md)。已有 Node 不必为本次指导更新升级框架或重编 DLL；需要整理实际产物时单独安排并验证。

## 发布与验证

按[发布方案](../../plans/2026-11-06-publish-node-dll-layout.md)更新当前版本示例和双语说明，核对版本门禁、文档及正式 Cargo 包内容。运行时代码未变，复用 0.25.1/0.25.0 已有运行时证据；正式 Cargo 发布保留 registry 依赖编译验证，并核对 docs.rs 全特性 API 与可选 format 页面。

源码候选、不可移动 Git 标签、crates.io 精确版本和 docs.rs 实际页面分别核实；具体发布结果归档在方案中，不将候选示例视为已可安装版本。本次没有新增 Windows DLL 加载或真实硬件验收。

## English

Framework 0.25.2 publishes Node DLL layout guidance. Keep one user-facing Node DLL at the top of each node's architecture directory, with accompanying third-party and helper runtime DLLs under `dependencies/`. Document the entry filename, architecture, and dependency purpose. No empty dependency directory or `references/` directory is required.

Actual artifact rearrangement requires working dependency resolution and target-platform loading checks. This release does not change Pack or loading code. Existing nodes need no framework upgrade for this guidance. Runtime code, macros, exact internal dependencies, other crates/tools, ABI/protocols, and MSRV are unchanged. Verify the source tag, registry package provenance, formal package build, and exact-version documentation separately; see the release plan for actual results.
