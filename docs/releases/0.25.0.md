# 0.25.0：现有 Lease 标签接入跨 DLL 节点资源所有权

源码候选：框架 0.25.0、lease 0.17.0。宏保持 0.22.0，标签及参数布局不变；其他组件不升版。C ABI v7、配置租约 v2 不变，资源代理协议升至 v2。

Lease 模式下首次初始化创建唯一节点对象并打开资源，后续 DLL 只取得代理；完整业务调用互斥。每个本地引用关闭只减引用，最后引用调用设备关闭、析构，再释放租约。初始化输出与节点状态共用；完整规范化 Config、Init Input 原始文本与命名接口必须一致。不同业务状态/类型共用物理连接仍使用通信层 SharedResource，不将两者混为同一能力。

升级前停止全部资源代理 v1 进程。源码候选不代表 registry 已发布，独立节点只有所需版本发布后才能更新精确依赖并重建；禁止本地覆盖。复制/改名旧 DLL 不会获得新行为。本次不发布 crates.io，不修改相邻独立节点，也没有恒惠项目源码或 COM5 硬件。

新增验证入口见[共享资源手册](../shared-resources.md)。验证范围覆盖真实原生动态库加载、独占文件资源及生命周期；现场 Windows COM5 通信需在目标设备上另行验证。

## English

Source candidates: framework 0.25.0 and lease 0.17.0. Macro syntax and macro crate 0.22.0 are unchanged. Existing Lease annotations now share one node owner: construct once, forward serialized complete operations, close/drop on the last reference, then release the lease. Node state is shared; named interfaces and all normalized initialization Config and Init Input text must match. Independent business state or different node interfaces sharing a connection still use a communication-layer SharedResource provider.

Resource protocol v2 adds final-close request/response frames and uses v2 endpoints/owner-lock directories. Stop all v1 resource participants before upgrading. Configuration lease v2 and C ABI v7 are unchanged. This task does not publish the candidate, change independent-node registry dependencies, or claim physical COM5 validation. Existing DLLs must be rebuilt after the required versions are published.
