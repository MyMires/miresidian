# TestFlow 0.14：按通道映射调用参数

日期：2026-11-19。所属组件：miresidian_testflow_windows；拟议目标版本：0.14.0。

## 当前决策与授权

用户要求讨论 TestFlow 多通道测试方案，参考测试平台表格，比较多种语法，并明确“优先采纳 C”。当前优先采用“业务方法名 + JSON 通道对象”，单通道与多通道使用同一结构；不增加 MultiChannel 包装指令。

本轮仅归档方案与选择依据，不开始产品实现、升版、推送或发布。优先选定语法不代表下文其他建议已获确认，也不代表该语法已由当前工具支持。

```text
# 单通道形式
发送({"ch1": ["AA", "hex"]})

# 多通道形式
发送({
    "ch1": ["AA", "hex"],
    "ch3": ["BB", "hex"]
})
```

此前比较：A 为按位置排列的通道数组，跳号需要 null 占位；B 为 ch1 = [...] 命名参数；C 为标准 JSON 通道对象；D 为每个业务参数携带通道值数组。保留其他方案作为讨论记录，不同时引入多套新语法。早期 MultiChannel 包装指令已被用户否决。

## 现状与资料依据

- 当前工具源码版本为 0.13.0，flow.rs 与 runner.ps1 均按物理行解析调用，仅接受字符串参数；尚不支持对象参数或多行调用。旧形式如 发送("AA", "hex") 已存在，兼容策略须明确。
- DLL 通过 GetFunctions/GetInitConfig 提供方法与初始化元数据；现有执行器按 TB 文本契约解析，ABI 7–9 使用三参数入口，ABI 10 使用单 JSON 请求入口。platform = 0 使用 DLL 固定默认平台，不保证自定义 DLL 的默认平台一定是 TB。
- TB 适配器以 Input[0] = "共享" 识别多通道输入，以后续每个字符串表示一个槽位，槽位内部按英文逗号拆分并 trim；输出将各通道字段用逗号拼接，不能无损反推出字段边界。
- 设计参考为本地 ate_editor/src/types/index.ts、RowEditorDialog.vue、DevEditorDialog.vue、types/__tests__/index.spec.ts，以及 ate-project/README.md 和合成测试。主表区分方法、ch1–ch6 输入、输出映射、线程和共享列；驱动表另存各通道初始化参数。编辑器源码未证明线程/共享列与框架策略的运行时对应关系，不直接映射。
- 批量读取真实客户工程行曾被自动审批拒绝，原因是提取范围超过必要样本且可能含敏感数据；本方案不引用客户行内容，也不把合成样例视为真实平台或硬件验证。

## 建议契约：仍须收敛后实施

1. 普通业务方法仅接收一个 JSON 对象，键为 chN，值为按 DLL 元数据顺序排列的字符串数组。建议 N 为无前导零的正整数，拒绝非法/重复键、非字符串参数、空对象及对象与旧位置参数混用。新语法不用于 Config、Delay 或框架固定查询/生命周期操作。
2. 通道按编号定位，不按 JSON 属性书写顺序排列；省略的中间通道跳过。建议结果范围为 ch1 到最大显式编号，最高编号须在分配槽位前检查容量，避免稀疏大编号导致无界分配。是否允许显式 null 保留尾部跳过位置、容量的来源与数值，均待确定，不把表格的六列硬编码为框架上限。
3. 旧字符串参数形式建议继续作为普通单通道调用。新对象仅含 ch1 时，是否也走普通单通道入口，或始终表示多通道请求，尚待决定；只有 ch3 时须保留前两个槽位，不能把它压缩成普通调用。此选择影响未声明 instance 节点是否接受对象单通道形式。
4. 建议支持多行调用及独立注释行。收集完整语句须识别 JSON 字符串与转义，不以字符串内的括号结束语句；保留起止行号，在 Rust 检查器与 Windows PowerShell 5.1 执行器中保持一致。JSON 对象不引入尾逗号、行内注释或其他非标准扩展。
5. 一次多通道请求只使用当前一份 Config 定位一个对象。Sequential、Parallel、Broadcast 沿用框架，不在语法中再指定；Parallel 不承诺同对象业务重叠，Broadcast 固定执行通道1一次，源通道跳过则整批跳过。不同 Config 的并发测试不是此语法的隐含能力。
6. 参数包含逗号、首尾空白、空字符串、零参数通道 [] 时，当前 TB 编码不能完整表达其语义。实施前比较“首版明确拒绝不能表达的值”与“同步扩展平台协议”，确定范围及版本影响；禁止静默改值、将 [] 当跳过，或增加只有工具理解的转义。batch/encoding 仍按实际方法元数据提供的槽位传入。默认值与参数数量错误采用工具预检还是保留框架跳过规则，也须明确；不能在广播非源通道上擅自增加业务类型解析。
7. 输出按通道编号显示原始文本；不能把空返回值直接标记为跳过，也不能用逗号再次切分字段。表格输出变量绑定、表达式求值与断言不因采用 C 语法自动纳入实现；若需要，先追加具体设计。
8. 不支持多通道的节点、非 TB 默认平台及旧 ABI 的实际兼容范围须明确检测或限制方式；当前元数据不能证明的能力不可凭显示名称推断。运行错误保留 status/code/message 和已有通道上下文，不自动重试或声称其他通道未执行；退出继续使用现有自动关闭流程，不增加会话或资源所有者。
