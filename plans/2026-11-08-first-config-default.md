## 目标与边界

- Node 初始化存在业务 Config 时，第一个业务 Config 必须在描述中声明非空、符合参数类型及业务约束的默认值，供宿主预填；无业务 Config 的节点不适用。
- 按初始化参数实际通道与顺序确定首个 Config，包含默认来自 Config 的未标注参数，不计 Input、Handle、平台、执行方式及租约访问方式等框架追加项。该要求不指定实例键或资源键。
- 首个 Config 的要求优先于路径、开放文本和连续数值预填留空的通用规范；其余参数沿用现有规则。默认值须有业务依据，资料缺失时记录待确认事项，不凭空编造设备配置。
- 不改变宏编译检查、运行时补值、数值空白、空身份跳过、复用、关闭或设备通信行为；不修改现有独立 Node、初始化模板、运行时或测试夹具。

## 现状与设计

当前框架为 0.26.1，业务描述不生成运行时默认值；multiple/config 默认全量身份，原始空身份先于类型解析跳过初始化。主文档和审查项未要求首个 Config 默认值，技术手册存在路径、开放文本、连续数值一律留空的指导，需明确本次规范的适用例外。

在 skill 主流程加入强制决策规则，review 加入验收项，维护规则保留此项；不在 skill 复制固定框架版本或 API 手册。编码规范及宏驱动开发手册定义声明要求、宿主预填与运行时行为边界，Config 身份文档链接此规范并修正相关示例。UI 元数据与规划参考不需语义修改，但完整同步及检查。
