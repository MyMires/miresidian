# Node DLL 主入口与依赖目录规范

## 目标与授权

- 用户已确认“先按照以上简单的结构来要求”：让用户一眼识别应该调用的 Node DLL，避免多个 DLL 平铺造成混淆。
- 本次仅维护规范与 Node skill；不修改打包器、初始化模板、加载代码或既有节点产物，不增加加载白名单、依赖清单格式或安全隔离机制。

## 现状与设计

- 当前框架源码为 0.25.1，Pack 为 0.13.2。现有打包器只收集节点 DLL 和 ABI 头文件，未自动收集第三方 DLL。
- 沿用 `dist/<节点>/windows-x64/` 或 `windows-x86/`：对应架构目录顶层仅放一个供用户调用的 Node DLL；随附的第三方及辅助运行时 DLL 统一放入该目录下的 `dependencies/`，无此类依赖时无需创建空目录。
- 头文件保持既有位置；节点说明、CHANGELOG、manifest 保持发布根目录的既有布局。说明必须明确入口文件名和适用位数，辅助 DLL 不作为本节点对外调用入口。
- 本次不要求新增 `references/`。未来整理实际产物时须验证移入子目录后的依赖解析及目标 Windows 加载调用；目录命名不意味着系统自动搜索该目录，也不宣称当前 Pack 已支持自动收集。

## 实现方式与影响文件

1. 在 `docs/coding-standards.md` 的交付要求中写入规范及简单目录示例。
2. 在 `skills/miresidian-node/SKILL.md` 的交付阶段保留简短必需要求，并在 `references/review.md` 补充入口辨识与依赖加载检查。
3. `CHANGELOG.md` 归档带日期的纯规范修订。
4. 比较后将仓库 skill 完整同步到实际安装目录 `/config/.codex/skills/miresidian-node/`，包括主文档、参考、UI 元数据和维护规则；保留原有无关内容。修改安装目录需按环境权限执行。
5. 本方案记录实施和验收证据。

版本影响：无；仅新增维护与交付审查规范，不改变产品源码、现有可构建/可调用/可交付行为、模板、依赖或锁文件。框架 0.25.1、Pack 0.13.2 及其他组件保持各自版本；不移动已有标签，不新增无关产品版本标签。
