# Node 构建前展示 features 并由用户选择

日期：2026-11-11。初始状态：方案先行落盘。当前状态：实施及针对性检查完成，待提交与提交后标签核对。

## 目标与执行依据

用户要求更新 Node skill：构建项目时列出当前项目支持的 features、用途及功能配置，让用户选择。本任务落实该流程要求；不构建或修改串口/TCP Node，不改变产品 API 或工具行为。用户已授权此次 skill 更新，不属于新建或整体构建 Node，无额外方案确认条件。

## 现状与设计

仓库与 `/config/.codex/skills/miresidian-node/` 的全部 5 个文件已比较，一致。现有主流程要求核对实际依赖与启用能力，但缺少向用户展示完整可选项及选择门禁。

在 SKILL.md 的版本查证步骤加入 features 清单与选择要求：按目标 Node、实际框架/直接依赖版本查清支持项，区分项目 feature 与依赖能力；列出用途、默认启用与当前实际启用、关联配置、前置/组合约束及影响。区分编译开关和运行时 Config/Input/节点声明，不把二者混用。新项目从拟用的已发布版本资料查证，不提前初始化模板。提供建议和理由，由用户选择后记录到方案，再执行受影响的初始化、依赖修改与构建；已有明确选择可复用，维护时保留已确认组合，无需每次小修复重选。不能把默认项或推荐当作用户选择；无可选项明确说明。

主流程保留规则唯一详细定义；planning.md 通过链接要求方案记录选择及配置落地，review.md 增加简短验收项。UI 提示补充先展示 features 并选择。维护规则 AGENTS.md 不需改文，完整同步时仍包含它，不增加固定 feature/版本适配表。

| 场景 | 审查结果 |
| --- | --- |
| 新建普通节点 | 先查拟用已发布版本/模板，列清单与配置供选择；方案及选择成立后才初始化 |

| 已有明确选择或尚未选择 | 有效选择记录依据并复用；无选择保持待确认，不以默认、建议或沉默继续受影响步骤 |
