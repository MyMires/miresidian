# Miresidian Node skill 维护规则

仅约束 skill 维护。权威副本保存在 [MyMires/miresidian](https://github.com/MyMires/miresidian) 的 `skills/miresidian-node/`；目录托管于框架仓库，skill 的适用性与更新不绑定框架或工具发行版本。

- 安装副本通常在 `${CODEX_HOME:-$HOME/.codex}/skills/miresidian-node/` 或 `~/.dsh/skills/miresidian-node/`，以实际位置为准，不硬编码机器路径。
- 修改任一副本前比较完整文件清单和内容，保留并合并独有改动；大幅调整前备份完整原始副本。修改后在同次任务同步全部文件和明确删除项，包括引用、UI 元数据及本规则。另一份不可访问时明确报告未同步。
- 主文档保留 Node 项目开发流程、必要的方案确认、关键决策、官方资料查询规则和完成条件。开发审查项集中在 references/review.md；项目业务事实与专属门禁留在项目 AGENTS.md，不复制通用编程教材或仓库维护制度。
- 不维护框架、工具、ABI、协议或 MSRV 的固定适配版本表，不复制具体 API、宏语法或完整命令手册。框架和工具的技术契约由各自对应版本的官方文档、示例、发布包及源码提供；工具还应核对实际程序帮助。
- 官方入口保持精简，说明如何确定实际版本和选择同版本资料。分别识别每个目标 Node 的业务版本与框架依赖，不能要求 master/latest 与项目版本相同，也不能从框架版本推算独立组件、工具或协议版本。保留资料缺失及离线回退办法，不借机升级依赖。
- 框架或工具升版不要求修改、重新安装或同步 skill；只有开发流程、查询方式、关键决策或验收依据发生实际变化时才修订 skill。skill 变更也不要求已有节点升级，避免新增常驻适配矩阵、文档镜像及无实际需求的查询服务。
- 精简旧参考前核对官方资料覆盖。保留业务对象身份、配置兼容性与物理资源所有权的区分，以及输入输出完整性、失败清理和实际验证要求；具体规则归对应官方资料，避免出现两份技术契约。
- 同步后校验文件清单与内容一致、skill 格式、内部引用/锚点、官方入口及 UI 元数据；用新建普通节点、维护旧版本节点、共享资源节点及多个不同依赖版本节点的任务审查查询与决策路径。不携带缓存、备份或构建产物，不为纯 skill 规范变更重跑无关构建。
- skill 变更按实际内容评估版本影响，在仓库 CHANGELOG 的带日期规范修订中记录。纯 skill 规范不提升无关框架或工具版本，不移动既有标签；涉及产品可构建、可调用或可交付行为时另按仓库版本规则判断。未经用户要求不引入独立版本号或发布流程。
