# Miresidian Node 项目开发

围绕真实业务完成 Node 项目。已有节点按本次改动推进，保留适用的契约和依赖，不重复初始化。

## 适配版本

本文及全部参考描述下列源码版本的接口与行为：

| 组件 | 适配版本 |
| --- | --- |
| 框架 `miresidian` | 0.23.0 |
| 资源共享实现 `miresidian_lease` | 0.15.3 |
| CLI `miresidian_cli` | 0.3.1 |
| Pack `miresidian_pack` | 0.13.1 |
| Windows TestFlow `miresidian_testflow_windows` | 0.12.0 |
| Rust MSRV / C ABI / 配置租约 / 资源代理协议 | 1.89 / v7 / v2 / v1 |

节点只依赖 crates.io 已发布的框架精确版本，安装前确认所需版本已发布。项目或工具版本与本表不一致时，先查对应精确版本的源码、文档和帮助，确认 API、features 及调用布局后实施；升级须在任务范围内。

## 1. 明确需求与方案

读取目标项目 AGENTS.md、源码、调用说明和资源资料，确认业务操作、通信协议、配置、对象身份、错误、目标平台及交付范围。影响正确性的缺失信息先查资料，再询问；不猜测协议。

新建或整体构建 Node 项目时，业务编码前提交方案与实施计划，等待用户明确确认。方案说明职责、Config/Input/Output、资源生命周期、所选能力、验证和交付；结构有助于理解时附 Mermaid 类图。模板初始化可提前进行，业务实现须在确认后开始；方案调整后重新确认。局部维护按任务范围处理。

## 2. 设计节点契约

实现前读取 [Node 开发参考](references/node-development.md)，落实[固定入口职责](references/node-development.md#固定入口与节点职责)、操作、参数来源、完整选项、空白/缺参、单位及错误条件；复杂契约可用简表表达。

默认采用普通单实例。按需求选择能力，只读取相关参考：

| 需求 | feature 与参考 |
| --- | --- |
| 多实例或多通道 | `instances`：[声明与调用](references/instances.md) |
| 跨 DLL/进程协调配置或共用物理连接 | `lease`：[配置租约与资源代理](references/lease.md) |
| 同一对象按原参数类型展开多条记录 | `batch`：[参数展开](references/batch.md) |
| 显式输入/输出格式转换 | `format`：[编解码与槽位](references/format.md) |

所选能力须落实依赖 features、适用的宏声明或通信层接入及验收行为；需要多种能力时组合启用。共享独占连接时先明确物理资源身份与通信事务协议，不能将取得兼容租约视为已共享连接。

## 3. 构建并实现

新项目从模板起步，已有项目沿用原结构；初始化、构建或打包时查 [工具命令](references/commands.md)。按开发参考划分契约与业务，优先复用适用的现有实现。

先完成“验证配置 → 建立资源 → 执行业务 → 返回结果 → 关闭资源”的调用链，再补齐其他操作及失败路径。实现真实协议与生命周期，同步调用说明、注释和业务烟测。模板回显与模拟能力须明确标识。

## 4. 验证本次行为

按 [验证与审查](references/node-development.md#验证与审查) 选择相关检查，完成项目强制门禁及所选能力的验收。复用仍有效的结果，修复后先重跑失败项和直接受影响项；耗时检查先说明目的与预计耗时，超时后重新评估。

无目标资源时验证协议样本、模拟响应和资源状态，明确真实通信未验证。验证限定本次平台、位数与能力，必要证据齐备后结束。

## 5. 完成交付

按项目规则同步自身版本、真实锁文件、带日期的 CHANGELOG 和调用说明。DLL 交付还须提供目标产物、头文件、版本/架构/SHA-256 清单及可执行示例，并取得加载调用证据。

报告已实现业务、项目版本、产物位置、实际验证和剩余事项，分别说明模拟、DLL 调用与真实资源结果。提交、标签和发布依用户授权及项目规则执行；框架、节点与工具独立判断版本影响。
