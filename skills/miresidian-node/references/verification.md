# 节点验证与验收

验证的对象是本次节点实现及其交付行为。先明确要证明什么，再选测试或检查；不要以运行尽可能多的命令代替验收。

## 按改动选证据

以下按需求选择，不作为每次任务的全量清单。目标项目强制门禁仍须遵守。

| 本次工作 | 应取得的相关证据 |
| --- | --- |
| 新建节点并实现业务 | 项目可编译；配置/方法描述与设计一致；主要业务及生命周期有针对性验证 |
| 修改某个操作或协议 | 正常响应、相关边界/错误样本；缺陷修复有复现用例；契约变更同步说明 |
| 修改初始化、关闭或连接持有方式 | 成功调用链、初始化部分失败清理、关闭释放和受影响的再次使用行为 |
| 引入多实例或资源共享 | 对象身份与隔离、配置冲突、相关并发/共享行为；不外推到全部框架策略 |
| 修改配置、默认值或输出 | 值来源、顺序、单位、默认/缺失/无效输入及实际输出与描述一致 |
| 交付 Windows DLL | 指定位数编译/打包；实际加载、注册与 ABI 调用；发布清单与产物一致 |
| 仅修改注释、文档或 skill | 内容、命令、引用、格式和适用版本；无需重复编译整个项目 |

新写的测试应能发现实际行为错误。避免只验证私有实现形状、重复代码逻辑或无关框架功能。简单文档修改不新增形式化测试。

## 业务与协议

利用设备协议样本或模拟传输验证实际解析和状态变化。例如，变更分帧时覆盖完整帧、截断和与该协议有关的异常；变更超时规则时验证超时及资源/状态是否符合设计，而不是扩展为所有通信库的压力测试。

正常输出应有可判断的期望值。失败用例应确认正确失败，不能把任意非零退出视为预期通过。

模拟证明的是协议和逻辑，不是物理设备可用。无设备时不启动真实硬件流程反复等待；说明缺少的设备及剩余验收项。已有硬件授权和条件时验证本次业务涉及的操作，注意不可重复执行的设备副作用。

## 生命周期与框架契约

验证所改动的相关路径：初始化成功后调用业务并关闭；初始化失败不泄漏临时资源；未初始化/已关闭的调用符合框架契约；关闭后资源确已释放。重复关闭或重新初始化的期望以所选框架和节点契约为准，不自行假设业务方法会被再次执行。

涉及参数或方法声明时，核对实际注册元数据，特别是 Config/Input 顺序、操作名称和输出。仅源码出现 operation 标注不能证明最终 DLL 已注册成功。

## DLL 与可执行烟测

交付 DLL 时，使用要求架构的加载环境验证实际产物。至少核对版本、方法/初始化描述及本次可运行的业务调用链；导出符号存在不等于加载和调用成功。两种位数都交付时分别取得证据。

TestFlow 应对应节点真实方法和配置，并有可判断的输出/失败结果。模板 Echo 只验证模板回显链；业务替换后不能继续把 Echo 成功当作业务通过。静态检查、生成 BAT、执行 BAT、真实设备成功分别报告。

核对本次 manifest 中的节点/框架/ABI、架构和 SHA-256 与实际产物一致。旧 dist 目录中有文件不能证明它属于本次构建。

## 控制验证范围与耗时

- 先选能证明相关行为的最小集合，优先运行能尽早发现问题的检查。局部变更限定节点/crate、测试目标和必要特性。
- 源码、依赖、构建配置、工具版本、环境未发生相关变化时复用已通过结果，注明结果对本次工作的适用性。
- 失败后先修复并重跑失败项及直接受影响项；只有新改动、新失败证据或未覆盖的交付要求才扩大。
- 耗时检查先说明目标与预计耗时。超出预估时报告原因并判断剩余必要性，避免反复轮询、全量日志和等价重跑。
- 不为单个节点重跑整个框架和工具链，不默认测试全部 OS/位数。打包已包含构建，不重复安排等价 release 构建。
- 无关问题记录待办；直接影响本次交付的问题须处理或明确报告。必要证据具备后停止验证，未验证/失败项不能写成通过。

## 完成判定与报告

按任务交付深度判定：源码完成需要真实实现和相应业务证据；DLL 交付还需要目标产物与加载调用证据；真实设备验收需要真实设备结果。证据不具备时明确交付到哪一层，不扩写为“全部完成”。

交付报告聚焦已实现业务、项目版本/产物、实际验证及其结论、复用证据、未验证范围和已知限制。工具能运行、模板能生成或打包成功均不是业务完成的替代证据。
