# 节点设计与实现约束

以项目精确依赖的已发布框架为准。不要把框架工作区尚未发布的版本或能力直接写入独立节点。

## 项目边界

一个独立节点 crate 声明 cdylib，并从 crates.io 精确依赖框架，由 Cargo 维护真实 Cargo.lock。一个节点 crate 声明一个具体节点；静态检查不展开宏、别名或条件编译，不用多份条件节点声明切换同一节点。

lib.rs 只承担入口、模块声明和必要导出。node.rs 只集中放置宏标记的节点结构体与契约方法，附带必需的 use/impl、对象字段和契约注释，方法体简短委托业务对象并做直接映射；设备内部状态、状态检查与业务流程由业务对象管理；操作调用的业务辅助方法、函数及子逻辑不得定义在 node.rs，具体规则见 [node.rs 契约可读性](project-standards.md#noders-契约可读性)。已有成熟业务抽象优先复用，不为简单节点建立通用驱动框架。

Node 项目负责资源连接、协议和业务实现，其中 node.rs 声明平台契约、业务对象承载具体实现；运行时负责生命周期调度、跨语言转换和 ABI 支撑；属性宏生成平台契约与导出。不能为实现业务把资源专有依赖放入框架，或把框架生成代码复制到节点。

## 源码职责与测试布局

实现前必须读取并执行 [Node 项目规范](project-standards.md)。模块职责、依赖方向、文件规模、测试位置及结构审查以该文档为统一入口；本文件聚焦框架契约，不另行规定目录模板或测试外置条件。

## 从业务划分 Config、Input 和 Output

Config 描述初始化与对象关联需要的业务配置，Input 描述当前方法调用的输入，Output 表达业务结果。逐项明确 Rust 类型、来源、平台名称、单位、默认值、范围和失败条件。

平台选项用 `/` 分隔，`-` 用于分隔实际值与显示值（例如 `Odd-奇校验`），不要将 `-` 放在实际值或单独的显示项中。数据格式选项可用 `UTF_8`，但必须先确认节点精确依赖的已发布框架支持该别名：codec 0.14.1 及对应框架版本起支持；旧版本可用 `UTF8`。`UTF-8` 仍是字符编码的标准名称，不能因此改写普通文档或 ABI 编码名称。为参数声明选择值后，验证平台描述及实际输入均能正确解析。

### 有限取值必须声明完整选项

型号、模式、校验方式、协议类型等具有明确且有限合法取值的 Config/Input 参数，必须在宏参数描述中声明完整的平台选项，包含当前实现实际支持的所有可选值。只写默认值、只列默认项或部分常用项均不合格；默认值必须属于该集合，文档中的取值表不能代替宏契约声明。

- 先从实际实现、目标资源资料和既有契约核实支持集合；不得猜测或列出尚未实现的值。修改支持范围时同步宏选项、内部解析/枚举、默认值、文档和相关测试；已有节点要按自身版本规则处理契约变化。
- 每个选项使用稳定的实际值；显示值仅作界面说明，不能与其他实际值或显示值产生歧义。选项格式沿用上一段规则，例如 `校验位:None-无校验/Odd-奇校验/Even-偶校验`；示例值须替换为当前实现真实支持的集合，不能机械照抄。
- Rust 内部优先使用具名 enum 表达这些业务选择，枚举及转换实现放在对应业务/协议模块，不能定义在 node.rs。保留 String 或基础类型时须有实际接口复用等理由，不能仅因外部以文本传值就让整个业务流程依靠字符串匹配。
- 核实项目精确依赖的已发布框架是否支持目标枚举直接作为契约参数；支持时复用其已有转换能力。不支持时外部可继续使用 String/基础类型，通过业务模块边界的解析转换成枚举，node.rs 只保留宏标注与简短委托，不手写业务解析逻辑。
- 外部规范选项值与对外可配置的枚举变体必须有明确对应；别名和显示名统一转换为相应规范值。即使平台界面提供选项，运行时仍须拒绝集合之外的值，在相关资源操作或副作用之前失败，不得把未知值静默回退为默认值。
- 连续数值、开放地址、任意文本及普通数值范围仍按实际范围/格式校验；不能因 Rust 类型的表示范围有限，就把所有数值展开成选项。离散业务集合即使只有一个当前合法值，也不能用默认值冒充选项声明；如需移除该配置，应按明确的契约变更另行处理。

### 初始化配置与参数来源

有业务初始化 Config 时，第一个业务 Config 必须是节点对象主键，例如连接地址、端口名或逻辑资源标识。超时、通信参数等不应替代对象身份。无业务配置的最小单实例节点允许空 Config，不为了满足形式而伪造主键。

初始化默认从 Config 读取参数，其他操作默认从 Input 读取；单个参数可显式标注覆盖来源：

```rust
#[miresidian::operation]
fn init_device(
    #[miresidian::config("连接地址")] address: String,
    #[miresidian::config("超时/ms:1000")] timeout_ms: u64,
) -> MiresidianResult<Self>
```

这只是签名示意，方法体必须按实际目标资源实现。业务方法中的 Input 也应采用实际含义和单位；输出标注放在方法上，数量与业务输出一致。不要在节点手工拼接平台响应 JSON。

## 节点与方法声明

使用结构体上的 node 宏声明节点；生命周期及业务方法使用 operation。初始化是无 self 关联函数，返回 MiresidianResult<Self> 或 MiresidianResult<(Self, T)>，后者只有 T 是业务输出。关闭及普通业务方法使用 &mut self。

不添加旧的 node_impl，不手写 DeviceNode 实现、操作字符串分发、GetFunctions、GetInitConfig 或 C ABI 导出。固定方法映射如下：

| 节点侧 | 对外行为 |
| --- | --- |
| init_device，标注 operation | InitDevice，构造实际业务对象 |
| close_device，标注 operation | CloseDevice，关闭对象资源 |
| 普通标注方法 | 显式操作名称，或从 snake_case 自动转换为 PascalCase |
| 可选的无 self get_port_no，标注 operation | GetPortNO，临时探测并自行回收资源 |

GetFunctions、GetInitConfig、GetFrameworkVersion、GetProjectVersion 及 CloseAllDevices 由框架提供，无需手写占位。常驻查询无需初始化；业务调用按正确配置执行初始化后再调用。

选择平台可表达的类型，如 String、数值、bool、Option 和基础类型 Vec；确认所选版本对具体类型/输出组合的支持。使用框架已有 HEX/Base64、文本与数组编解码，不重新设计平台字符串协议。

## 通信、状态与错误

先用目标资源资料确定请求格式、结束条件、帧长度、校验、编码和超时语义，再实现协议。输入验证发生在相关副作用前；响应不能只取“看起来可用”的片段而忽略资源错误或残帧。

将连接和业务状态放在节点持有的对象中；避免可变全局状态。初始化部分失败时由函数内部所有权、Drop 或显式回滚释放资源；返回成功后由节点生命周期管理。

完整请求—响应必须避免交错访问。根据真实资源共享方式处理同步，不把实例锁当成跨资源或跨进程的事务保护。自动重试必须考虑操作是否幂等，以及超时前目标资源可能已执行的副作用。

预期错误通过 MiresidianResult 返回，并包含有用的操作/资源上下文；使用所选框架版本实际提供的错误 API，不猜测构造函数。不吞掉错误后返回零值、空文本或成功状态。不依赖 panic 处理正常超时、无效配置和资源拒绝。

关闭释放连接和后台资源，失败时仍尽力清理其余资源。不要在关闭后让遗留任务继续使用句柄。注释说明资源归属和清理责任。

## 按需求启用实例与共享能力

依赖 features、节点声明和运行时行为必须配套，具体选择与可复制的配置见 [框架能力与 features](features.md)。不能只描述概念而不落实 Cargo.toml 和节点代码。

先判断是否需要同时保留多个节点对象。默认是单实例；只开启 instances feature 不改变默认行为，需要同时启用依赖 feature 和对应 instances(...) 声明。

multiple/config 以 Config[0] 关联对象：空主键跳过初始化，相同主键且配置相同复用，配置不一致报错。handle 关联由框架在业务配置后追加 Handle，不能把它混入业务参数索引。

多实例、多通道执行、租约是不同能力，不因存在多个节点对象就全部开启。租约不代表物理句柄共享或通信事务互斥。需要这些能力时查所选发布版本的实例/租约说明，确认配置布局和并发语义再实现；不要创造框架替代协议。

## ABI 与调用说明

ABI v7 由框架生成 miresidian_abi_version、miresidian_invoke 和 miresidian_invoke_with。以本次依赖提供的 miresidian.h 为正式签名来源。

Config/Input 是 UTF-8 JSON 字符串数组，例如 ["COM3","9600"]。响应含 status、code、message、output；业务结果在 output 字符串数组中，以 status/稳定 code 判断失败，不解析 message。返回文本由 DLL 当前线程持有，调用方在同线程下一次调用前复制，不释放返回指针。

docs/<节点显示名>.md 应说明实际支持的 DLL/位数、ABI 签名、业务配置、方法输入/输出、单位/默认值、错误、返回所有权/有效期、调用顺序和示例。文档应能指导真实调用；文件非空不等于说明完整。

若需进一步核对，优先读取与目标版本相符的框架 docs/宏驱动开发.md、docs/instances.md、docs/c-abi.md。源码仓库为 [MyMires/miresidian](https://github.com/MyMires/miresidian)，[发布版 API](https://docs.rs/miresidian) 应切换到项目精确版本；不默认 HEAD/latest 与项目一致。
