# Node 开发与交付检查

设计契约、审查实现或交付前按本次改动选择相关项。具体签名、语法、默认值、错误和支持范围，按 [官方资料查询规则](../SKILL.md#2-确定版本并查阅官方资料) 核对；本页不定义框架或工具的版本契约。

## 方案文件与实施一致性

- 是否在初始化、修改代码、依赖或交付实施前建立/更新任务方案，覆盖新建、局部修复和维护？是否提供方案路径，满足用户要求的确认条件？
- 方案是否具体说明目标、实际版本与依据、实现方式、职责、调用链、资源共享粒度/状态/生命周期、接口与错误、文件/版本影响和逐项验收？
- 实际结构、接口、所有权、默认/错误、实施步骤和验证是否严格对应当前方案？调整是否先修订文件、说明原因/影响并完成必要确认，是否存在先代码后补方案或擅自降低验收？
- 交付是否逐项对应“需求 → 设计 → 步骤/代码 → 验证证据”，如实保留未完成/未验证/受阻项及修订依据？具体结构见[方案文件与实施约束](planning.md)。

## 项目与职责

- 目标 Node 自身版本、业务契约、实际依赖及工具版本是否已确认，采用的技术资料是否对应这些版本？多个节点是否分别核对，跨节点协作是否确认 ABI 和协议兼容性？新增依赖是否适合目标平台、许可证与工具链要求？
- 所需能力是否落实到正常交付的依赖配置、节点声明和通信接入，而非仅在临时检查时启用？
- lib.rs 是否保持入口、模块声明和必要导出职责？节点结构体和宏标注方法是否集中展示契约并仅作委托或直接参数/结果映射？辅助类型、常量、业务流程、校验、I/O 和测试是否归所属业务模块？
- 下层业务、协议与通信是否独立于平台索引及 ABI 文本？资源、状态和缓存是否有明确管理者？现有有效实现是否已复用？
- 新模块和抽象是否有独立职责与真实调用方？沿用项目命名和模块规则，避免空模块、纯转发层及为测试扩大公开 API。

## 契约与输入输出

- 操作、初始化、关闭及可选发现能力是否各有明确用途、参数来源、返回与失败边界？框架生成的入口、编解码和调度是否由对应框架能力承担？
- Config/Input/Output 的顺序、名称、类型、单位、业务范围、必填性、缺失/空白和输出槽位是否明确，并与实际注册元数据及调用示例一致？框架追加字段是否按实际查询结果组织？
- 是否按节点开发手册的“参数声明规范”核对默认/预填要求（含首个业务 Config）、选项和显示值，且未将宿主预填当作运行时补值？
- 参数校验是否在相应资源操作和副作用前完成？无业务结果是否按框架契约返回，错误是否包含业务上下文，而非成功默认值或 panic？

## 生命周期与通信

- 正常初始化、业务调用和关闭是否贯通？构造部分失败是否回收资源，复用与配置变更是否符合所选对象策略？发现操作是否释放临时资源？
- 断连、普通业务错误和故障后是否能清理连接及后台任务？清理是否依赖额外的调用方输入，是否误关其他对象或仍被使用的资源？
- 协议帧边界、长度、校验、编码和超时是否有资料或样本依据？完整请求—响应是否在所需互斥范围内，避免交错读取？
- 异步、截止时间或取消被使用时，是否确认实际完成和清理？是否区分取消请求、等待超时与设备动作已经停止，并核实有副作用操作的重试条件？

## 所选能力

仅检查实际使用的能力，预期行为依据相应版本资料：

| 能力 | 需要取得的证据 |
| --- | --- |
| 多实例与多通道 | 对象定位、同身份复用或冲突、独立状态和目标关闭；所选执行策略的调用次数、跳过/失败、输出对齐及副作用 |
| 配置协调 | 相同物理资源的兼容与冲突，失败和关闭后的正确释放；不以任意非零退出代替预期错误断言 |
| 共享物理资源 | 交付范围内不同 DLL/进程的实际附着与通信，连接创建次数、事务互斥、独立业务状态、关闭一个与关闭最后一个代理的结果，以及所有者故障和超时边界 |
| 批量与格式转换 | 使用类型的解析、记录边界、数据/格式列对齐与广播、输出槽位、选择器布局及非法输入前置拒绝；发生业务或输出错误后的停止和副作用 |

## 验证与交付

- 正常业务、相关边界、失败及资源释放是否有有效证据？缺陷修复是否保留可复现的回归；重组是否保留原有有效断言？
- 单元测试是否验证业务，集成测试是否验证公开契约或跨模块行为？检查是否限定本次改动、所选能力及交付平台，已有结果是否仍适用？
- 调用说明是否涵盖配置与选项、单位、输入输出、错误、顺序、实际 ABI 及内存生命周期，并提供可执行的真实业务示例？README 和项目 AGENTS.md 是否记录有效的业务边界、开发入口及命令？
- DLL、头文件、清单、目标架构、版本和 SHA-256 是否对应本次产物？是否在目标平台实际加载，并核对元数据和相关业务调用？
- 交付目录及依赖组织是否符合本次查阅的开发规范，并取得实际依赖解析及目标平台加载证据？
- 是否分别记录结构检查、编译、打包、DLL 调用、模拟和真实资源验证？未运行、受阻或失败的部分是否如实报告，避免以模板回显或旧产物作为完成依据？

仅修改 skill 或规范时，检查内容、资料入口、内部引用、格式、UI 元数据与完整副本同步即可，不扩大到无关构建或硬件测试。
