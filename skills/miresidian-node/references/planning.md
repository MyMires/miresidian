# 方案文件与实施约束

方案是否需要、何时生成、存放位置、复用及确认条件，统一按[主流程](../SKILL.md#2-初始化项目并按范围管理方案)判断；本页只补充文件结构和实施中的变更控制。框架自身更新遵循仓库规则，技术 API 和工具命令仍查询实际版本资料。

## 建议文件结构

以下结构可按任务合并，不能用空标题代替关键决策；不适用项注明原因。方案必须足够具体，使另一位实现者无需猜测关键设计即可执行。

需要方案且涉及新建、整体构建或 feature 组合调整时，按[features 清单与用户选择](../SKILL.md#构建前展示-features-并由用户选择)在方案中记录清单依据、用户选择或待确认项、关联配置、构建/交付落地及验收；尚未选择的事项不能写成已确认设计。

```markdown
# 日期与任务主题

状态：方案中 / 待确认 / 实施中 / 验收中 / 已完成 / 受阻。
执行依据：对应用户指令或方案确认；待确认事项如实列出。

## 目标与范围

用户需要的可观察行为、非目标、保留边界、假设及待确认问题。

## 现状与依据

现有代码路径、实际 Node/依赖/工具版本、相关技术资料和当前缺口。

## 具体方案

职责及模块、类型/接口、Config/Input/Output、完整调用链；
资源身份、所有者、共享粒度与业务状态、引用/关闭顺序、错误/失败清理；
并发、超时、取消及重试边界。复杂关系可配图，不适用项标明。

## 影响与兼容性

待改文件、保留实现、依赖/版本影响、ABI/协议及迁移、文档与交付范围。

## 实施与验收矩阵

| 需求/设计项 | 实施步骤及目标文件 | 前置条件 | 验证方法与通过标准 | 状态/证据 |
| --- | --- | --- | --- | --- |

## 修订与实际结果

调整原因、原决策和新方案、影响与确认依据；逐项完成情况、
实际验证范围、未验证/受阻事项及证据位置。
```

## 实现必须与文件一致

以下仅适用于有方案的任务。每一步核对当前有效方案：结构、接口、具体实现方式、共享粒度、所有权/生命周期、默认与错误、文件范围和验收不得擅自替换。只有“使用租约”“通过测试”等笼统任务名不构成实现方案；需写清资源从何创建、业务从何调用、何时释放及怎样证明交付效果。

方案需要调整时，先停止受影响步骤并修订文件，记录原因、原决策、影响和执行依据。关键架构、接口、共享状态、生命周期、兼容性或验收变化先满足用户要求的确认条件；其他已授权且不依赖该变更的工作可继续。不得先执行再补记录，不得削弱验收来掩盖实现缺口。

交付前按矩阵追踪需求、设计、实际代码和验证证据，未实现或未验证不能标完成。保留方案修订与实际结果，不伪造文件在实施前已存在的记录。纯方案/skill/规范更新只做相关内容、引用、格式和版本门禁校验，不触发无关编译或硬件验证。
